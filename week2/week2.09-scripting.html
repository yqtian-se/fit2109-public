2.9 Shell Scripting Basics

A shell script is a plain text file containing shell commands. The shell reads and executes them exactly as if you had typed them at the prompt — the same evaluation rules, the same quoting requirements, the same exit status. Scripts make workflows repeatable: one command runs a whole sequence reliably.

Making a script runnable

Two things are required before you can run a script with ./script.sh:

  1. A shebang on line 1 — tells the OS which interpreter to use.
  2. The execute permission bit set on the file.
#!/usr/bin/env bash
# The shebang must be the very first line.
# #!/usr/bin/env bash finds Bash via PATH — portable across macOS and Linux.
echo "Hello from a script"
$ chmod u+x greet.sh   # add execute bit for owner
$ ./greet.sh
Hello from a script
Why #!/usr/bin/env bash? On macOS, /bin/bash is an old Bash 3.x kept for compatibility. Homebrew installs a modern Bash elsewhere. Using #!/usr/bin/env bash finds whichever bash is first on your $PATH, so scripts work consistently on macOS and Linux without hardcoding a path.

Positional arguments

Arguments passed when running a script are available as numbered variables:

VariableValue
$1, $2, …First, second, … positional argument.
$#Total number of arguments passed.
$@All arguments as separate words. Quote as "$@" to preserve spaces in individual arguments.
$0The name of the script itself.
${1:-default}Use $1 if set; otherwise use default.
 
#!/usr/bin/env bash
name=${1:-world}
echo "Hello, $name"
$ ./greet.sh
Hello, world
$ ./greet.sh Alice
Hello, Alice

Conditionals

The if statement branches on exit status. The [ ] test command evaluates conditions and returns 0 (true) or 1 (false):

#!/usr/bin/env bash
file="$1"
if [ -f "$file" ]; then
    echo "File exists: $file"
    wc -l < "$file"      # < feeds the file into wc -l via stdin (covered in Week 1)
else
    echo "File not found: $file" >&2  # >&2 sends this message to stderr, not stdout
    exit 1
fi

Common file test operators inside [ ]:

TestTrue when
-f "$path"Path exists and is a regular file.
-d "$path"Path exists and is a directory.
-e "$path"Path exists (any type).
-z "$str"String is empty.
-n "$str"String is non-empty.
"$a" = "$b"Strings are equal.
"$a" != "$b"Strings are not equal.

Loops

#!/usr/bin/env bash
# Loop over positional arguments
for file in "$@"; do
    if [ -f "$file" ]; then
        echo "$file: $(wc -l < "$file") lines"
    else
        echo "$file: not found" >&2
    fi
done
#!/usr/bin/env bash
# Loop over files matching a pattern
for log in logs/*.log; do
    echo "Processing $log"
    grep -c 'ERROR' "$log" || echo "  no errors"
done

Recognising Bash functions

Bash can also group commands into a function. A function gives a small command sequence a name so the script can call it more than once.

#!/usr/bin/env bash
warn() {
    echo "warning: $1" >&2
}

warn "missing input"
Inside a function, arguments restart Inside warn(), $1 means the first argument passed to warn, not necessarily the first argument passed to the whole script. This is one reason we treat functions as a recognition topic for now.
Write errors to stderr, not stdout Error messages should go to standard error (&2) so they do not contaminate the script's output when it is used in a pipeline: 
echo "Error: file not found" >&2
exit 1
A caller piping your script's stdout into another tool will only see clean output, not error messages mixed in.
