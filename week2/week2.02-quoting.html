2.2 Quoting Rules

Quoting is how you tell the shell which parts of a command line to leave alone. The shell has three quoting modes, each with different rules about what gets expanded and what gets treated as literal text.

The three quoting modes

ModeSyntaxWhat the shell doesWhen to use
No quotes $name, *.txt Variables expand. Globs expand. Results are word-split on whitespace. Only when you want word splitting or glob expansion — rarely.
Double quotes "$name" Variables and command substitutions expand. Spaces are preserved. Globs do not expand. Almost always — the safe default for variables.
Single quotes 'literal' Everything is literal. No expansion of any kind. No backslash escapes. When you need a truly literal string — e.g., regex patterns, JSON, or strings with $ signs.

Side-by-side comparison

$ file="Week 2 Materials/errors log.txt"

# No quotes: word-splits "Week", "2", "Materials/errors", "log.txt" — four args
$ ls $file
ls: Week: No such file or directory

# Double quotes: one argument, spaces preserved, variable expands
$ ls "$file"
Week 2 Materials/errors log.txt

# Single quotes: literally the string $file — variable does NOT expand
$ echo '$file'
$file

# Glob in double quotes: does NOT expand
$ echo "*.txt"
*.txt

# Glob without quotes: expands to matching filenames
$ echo *.txt
notes.txt summary.txt

The default rule: always quote variables

Unless you have a specific reason to want word splitting or glob expansion, always wrap variable references in double quotes:

# Safe patterns — use these by default
$ cp "$source" "$dest"
$ if [ -f "$file" ]; then ...   # if/then is introduced in section 2.9
$ grep "$pattern" "$logfile"
When you intentionally skip quotes There are two common cases where you deliberately leave quotes off:
  • Glob expansion: ls *.log — you want the shell to expand matching filenames.
  • Splitting a list: for f in $list — though this is fragile if elements contain spaces. Prefer passing items as separate arguments rather than packing them into one variable.

Mixing quote styles

You can concatenate quoted and unquoted sections within a single argument by placing them adjacent to each other:

# Both of these produce the same argument: /home/student/notes.txt
$ echo "$HOME"/notes.txt
$ echo "${HOME}/notes.txt"

# Embedding a literal single quote inside double quotes
$ echo "It's a shell"
It's a shell
Common trap — quotes in test expressions (The if [ ] syntax is introduced fully in section 2.9 — focus here on why quoting matters inside the brackets.)

Inside [ ] conditions, an unquoted variable that expands to empty breaks the test syntax. Always quote: 
# Dangerous: if $name is empty, [ ==  "Alice" ] is a syntax error
if [ $name == "Alice" ]; then ...

# Safe
if [ "$name" == "Alice" ]; then ...
Try this Predict the output of each line before running it: 
$ name="Dr. Tian"
$ echo Hello $name
$ echo "Hello $name"
$ echo 'Hello $name'
$ printf '%s\n' Hello $name
$ printf '%s\n' "Hello $name"
The printf calls again make word splitting visible. Count the lines of output for each.
