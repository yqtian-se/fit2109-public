2.8 Finding Files with find

find locates files using filesystem properties — name, type, permissions, size, modification time — not by searching file contents. Where grep searches inside files, find searches for files. Both are frequently combined in pipelines.

Basic syntax

find [starting-directory] [expression]

find walks the directory tree starting from the path you give it (usually . for the current directory) and evaluates the expression against each file it encounters. Files for which the expression is true are printed.

Essential predicates

PredicateMeaning
-name '*.log'Filename matches the glob pattern. Always quote the glob — otherwise the shell expands it before find sees it.
-type fRegular file (not a directory or symlink).
-type dDirectory.
-type lSymbolic link.
! -perm -u=xFiles that are not executable by their owner. The ! negates the predicate.
-size +1MFiles larger than 1 megabyte. Use k, M, G for units.
-newer ref.txtFiles modified more recently than ref.txt.
-maxdepth 2Search at most 2 levels deep.
-regex 'pattern'Full path matches the regex. See the note below.
-exec cmd {} +Run cmd on each result. {} is replaced by the filename; + batches arguments.

Common examples

# All Python files in the current tree
$ find . -type f -name '*.py'

# Shell scripts that are NOT executable by their owner
$ find . -type f -name '*.sh' ! -perm -u=x

# Search only one level deep
$ find . -maxdepth 1 -type f -name '*.log'

# Run grep on every Python file found
$ find . -type f -name '*.py' -exec grep -nE 'TODO|FIXME' {} +

# Full path regex — Linux/GNU find only (-regextype not available on macOS BSD find)
$ find . -regextype posix-extended \
     -type f -regex '.*/[a-z]+-[0-9]{4}\.log'

Time-based and size-based searches

# Files modified in the last 7 days
$ find . -type f -mtime -7

# Files NOT modified in the last 30 days (candidates for cleanup)
$ find . -type f -mtime +30

# Files larger than 1 MB
$ find . -type f -size +1M

# Files smaller than 1 KB (often empty or near-empty)
$ find . -type f -size -1k

# Empty files (size exactly 0)
$ find . -type f -empty

# Large Python files modified recently — combine predicates freely
$ find . -type f -name '*.py' -size +50k -mtime -7
-mtime units -mtime N counts in days. Use -mmin N for minutes instead. The - prefix means "less than N days ago" (more recent); + means "more than N days ago" (older).

OR conditions and counting

# Files matching EITHER of two patterns — use \( \) and -o for OR
$ find . -type f \( -name '*.py' -o -name '*.sh' \)

# All source files except those in a build directory
$ find . -type f -name '*.c' ! -path '*/build/*'

# Count how many files match (pipe find output into wc)
$ find . -type f -name '*.py' | wc -l

# Count total lines across all Python files
$ find . -type f -name '*.py' -exec cat {} + | wc -l

# List all directories (useful for auditing project structure)
$ find . -type d

# Print only filenames, not full paths — Linux/GNU find only (-printf not on macOS)
$ find . -type f -name '*.log' -printf '%f\n'
find -regex matches the full path, not just the filename find . -regex 'error.log' will not match ./logs/error.log because the regex must match the complete path ./logs/error.log, not just the filename part. You need: 
find . -regex '.*/error\.log'
Use -name when you only care about the filename; use -regex when you need to match the full path structure.

-exec vs piping to xargs

There are two common ways to run a command on each file find locates:

# -exec with + batches arguments (like xargs) — usually preferred
$ find . -name '*.log' -exec wc -l {} +

# -exec with \; runs the command once per file — slower, but needed when
# the command cannot accept multiple arguments
$ find . -name '*.log' -exec echo "Processing: {}" \;

# Equivalent with xargs (useful for complex pipelines)
$ find . -name '*.log' -print0 | xargs -0 wc -l
Quote the -name glob Always write find . -name '*.py', not find . -name *.py. Without quotes, the shell expands *.py to matching filenames in the current directory before find sees the argument — which is almost certainly not what you want.

Combining find with grep and sort

A common pattern is to use find to locate files and then pipe or exec into grep to search their contents, followed by further text processing:

# Find all log files, search each for ERROR, count and rank by frequency
$ find . -type f -name '*.log' -exec grep -h 'ERROR' {} + | sort | uniq -c | sort -nr

# -h suppresses the filename prefix from grep so only the matching lines flow
# into sort/uniq — otherwise filenames would break duplicate detection

This pipeline illustrates the Unix composition idea: find selects which files, grep -h selects which lines, and sort | uniq -c | sort -nr ranks the results — each tool doing one thing.

Try this 
$ mkdir -p demo/scripts demo/logs
$ touch demo/scripts/deploy.sh demo/scripts/build.sh demo/logs/app.log
$ chmod -x demo/scripts/build.sh     # remove execute bit
$ find demo -type f -name '*.sh'
$ find demo -type f -name '*.sh' ! -perm -u=x
Which script appears in the second command's output, and why?
