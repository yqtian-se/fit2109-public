Week 2: Shell Evaluation, Scripting, and Remote Access

Pre-reading · FIT2109 · Monash University

"The shell rewards careful habits and punishes careless assumptions." — Bash in the Wild, TOSEM 2022

By the end of this week you should be able to

  1. Explain quoting rules and predict how the shell evaluates a command.
  2. Use variables, export, and $? to control command-line behaviour.
  3. Construct grep, find, and text-processing pipelines using regular expressions.
  4. Write a basic shell script with arguments, conditionals, and loops.
  5. Apply set -u and set -o pipefail to improve script reliability.
  6. Use ssh and scp to access remote machines and transfer files.

A scenario

It is 11 pm. You wrote a script to back up files from a project folder called Week 2 Materials. The script ran without errors — or so you thought. You check the backup directory: it is empty. You run the script again with some extra echo calls and realise the problem: your variable dir holds the value Week 2 Materials, but because you wrote ls $dir instead of ls "$dir", the shell split it into two separate arguments — ls Week and 2 — neither of which matched anything. The backup command never saw the right path.

One missing pair of quotes. Three hours of confusion. This is what Week 2 is about: understanding exactly how the shell reads and rewrites your commands before running them, so that surprises like this become predictable rather than mysterious. By the end of this pre-reading you will be able to look at any shell command and trace through what the shell will actually execute.

Concept check — before you start What do you think echo $name does when name has never been set? And what about echo "$name"? Jot down your prediction — you will see the answer in Section 2.3.
