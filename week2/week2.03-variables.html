2.3 Variables and the Environment

The shell stores variables for its own use. A shell variable remains inside the current shell. When you mark that variable with export, the shell also includes it in the environment copied to each child process it launches. Understanding this distinction explains why tools like Python, make, or other scripts can or cannot see values you set at the command line.

Shell variables vs environment variables

The difference is determined by export, not by whether the name uses uppercase or lowercase letters. The examples use a different name for each case, so you can run them in order without one example affecting another:

PatternCurrent shell afterwardChild processesLifetime
LOCAL_COURSE=FIT2109 Can use $LOCAL_COURSE. Do not receive it. Until it is unset or the shell exits.
export SHARED_COURSE=FIT2109 Can use $SHARED_COURSE. Receive a copy of it. Until it is unset or the shell exits.
TEMP_COURSE=FIT2109 env TEMP_COURSE is not kept. Only env, and any process it starts, receives it. For this one command. 
# Shell variable: visible in this shell
$ LOCAL_COURSE=FIT2109
$ echo "$LOCAL_COURSE"
FIT2109

# Child process does NOT inherit this Shell-only variable
$ bash -c 'echo "Child sees: $LOCAL_COURSE"'
Child sees: 

# A separate exported variable is visible to child processes
$ export SHARED_COURSE=FIT2109
$ bash -c 'echo "Child sees: $SHARED_COURSE"'
Child sees: FIT2109
Why does the child start out empty? When a shell launches a child process, it copies its environment — the set of exported variables — into the child. Shell-local variables are never copied. The child has its own separate memory and cannot see anything the parent did not explicitly export. Uppercase names such as PATH and SHARED_COURSE are only a convention for commonly exported variables; capitalization does not make a variable an environment variable.

Useful ways to work with variables

PatternMeaningExample
name=value Assign a shell variable. No spaces around =. dir=/tmp/work
export name Mark variable for export to child processes. export PATH
export name=value Assign and export in one step. export EDITOR=vim
NAME=value cmd Set a variable for one command only — not the current shell, not persistent. DEBUG=1 ./script.sh
env List all current environment variables. env | grep PATH
${var:-default} Use default if var is unset or empty. name=${1:-world}

Per-command variable prefix

You can set an environment variable for a single command by placing NAME=value before the command name. The variable is visible to that command and its children — but not to your shell, and not to the next command you run.

# Set TEMP_COURSE only for this one invocation of env
$ TEMP_COURSE=FIT2109 env | grep '^TEMP_COURSE='
TEMP_COURSE=FIT2109

# Back in the parent shell: TEMP_COURSE is not set
$ printf 'Parent sees: <%s>\n' "$TEMP_COURSE"
Parent sees: <>

This pattern is common when running tools that read their configuration from environment variables — for example, setting PYTHONPATH or FLASK_ENV for a single test run without permanently changing your shell environment.

Command substitution

A variable does not have to be typed by hand — $(command) runs a command and substitutes its output into the line. This is how scripts capture a command's result for later use.

# Capture a command's output in a variable
$ today=$(date +%F)
$ echo "Backup name: logs-$today.tar"
Backup name: logs-2026-07-29.tar

# Or substitute directly inside another command
$ echo "This folder has $(ls | wc -l) entries"
This folder has 7 entries
Quote it like any other expansion The output of $(...) word-splits exactly like an unquoted variable does. Write "$(command)" when the output could contain spaces — the same habit as "$file".
