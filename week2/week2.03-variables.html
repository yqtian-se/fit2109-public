2.3 Variables and the Environment

The shell distinguishes between two kinds of variables: shell variables, which exist only in the current shell session, and environment variables, which are passed on to every child process the shell launches. Understanding the difference explains why tools like Python, make, or other scripts can or cannot see values you set at the command line.

Shell variables vs environment variables

# Shell variable: only visible in this shell
$ course=FIT2109
$ echo "$course"
FIT2109

# Child process does NOT inherit it yet
$ bash -c 'echo "Child sees: $course"'
Child sees: 

# export promotes it to the environment
$ export course
$ bash -c 'echo "Child sees: $course"'
Child sees: FIT2109
Why does the child start out empty? When a shell launches a child process, it copies its environment — the set of exported variables — into the child. Shell-local variables are never copied. The child has its own separate memory and cannot see anything the parent did not explicitly export.

Useful ways to work with variables

PatternMeaningExample
name=value Assign a shell variable. No spaces around =. dir=/tmp/work
export name Mark variable for export to child processes. export PATH
export name=value Assign and export in one step. export EDITOR=vim
NAME=value cmd Set a variable for one command only — not the current shell, not persistent. DEBUG=1 ./script.sh
env List all current environment variables. env | grep PATH
${var:-default} Use default if var is unset or empty. name=${1:-world}

Per-command variable prefix

You can set an environment variable for a single command by placing NAME=value before the command name. The variable is visible to that command and its children — but not to your shell, and not to the next command you run.

# Set COURSE only for this one invocation of env
$ COURSE=FIT2109 env | grep '^COURSE='
COURSE=FIT2109

# Back in the parent shell: COURSE is not set
$ echo "$COURSE"
             # empty

This pattern is common when running tools that read their configuration from environment variables — for example, setting PYTHONPATH or FLASK_ENV for a single test run without permanently changing your shell environment.
