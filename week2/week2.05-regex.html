2.5 Shell Globs vs Regular Expressions

Both globs and regular expressions use special characters to match patterns. They look superficially similar, which causes persistent confusion. They are, however, completely different languages — interpreted by different software at different points during command execution.

The fundamental difference

Shell globRegular expression
Who interprets it The shell, before the command runs. The tool (grep, find, sed, etc.), after the shell has passed arguments.
What it matches Filenames in the filesystem. Text content inside files, or strings in memory.
Typical context ls *.log, rm /tmp/*.tmp grep 'pattern' file, find -regex

Glob syntax

Globs are expanded by the shell into a list of matching filenames before the command ever runs:

GlobMatches
*Any string of characters (not including /).
?Exactly one character.
[abc]One character that is a, b, or c.
[0-9]One digit.
**Any path including subdirectories (requires globstar option in Bash).
 
# Shell expands *.log to matching filenames before ls sees them
$ ls *.log
access.log  app.log  error.log

# ? matches exactly one character
$ ls app-?.log
app-1.log  app-2.log

Regex syntax (basics)

Regular expressions are passed to a tool as a string argument. The tool — not the shell — decides what they mean:

RegexMatches
.Any single character (in regex, not just filenames).
.*Any string of characters (zero or more of .).
[0-9]+One or more digits (requires -E — the extended regex flag, introduced in section 2.6).
^ERRORLine starting with ERROR.
\.log$Line ending with .log (backslash escapes the literal dot).
WARN(ING)?Matches WARN or WARNING (requires -E).
 
# grep -E uses extended regex — quote the pattern to prevent shell interpretation
$ grep -E 'WARN(ING)?' app.log
$ grep -E '^[0-9]{4}-' app.log   # lines starting with a date like 2026-
Common mistake: confusing * in globs and regex
  • In a shell glob, *.log means "any filename ending in .log".
  • In a regex, * means "zero or more of the preceding element" — but in *.log there is nothing preceding the *, making it a syntax error in most tools. It does not mean "any characters then .log".
  • The regex for "any characters then .log" is .*\.log.
Always quote regex patterns to prevent the shell from trying to glob-expand them: grep -E 'pattern', not grep -E pattern.

Side-by-side examples

# GLOB: shell expands *.log to filenames, then ls lists them
$ ls *.log

# REGEX: grep searches file content for lines matching the pattern
$ grep '\.log$' filenames.txt   # find lines that end in .log

# Both at once: glob selects which files to search; regex selects which lines
$ grep -E 'ERROR [0-9]+' *.log
Try this Create a few test files and predict which commands match what: 
$ touch app.log server.log notes.txt
$ ls *.log               # glob: shell expands before ls
$ ls "*.log"             # quoted: shell does NOT expand — ls sees literal *.log
$ echo app.log | grep '\.log$'   # regex: matches the text "app.log"
