2.6 Searching Text with grep

grep searches files (or standard input) for lines matching a pattern and prints matching lines. It is one of the most used Unix tools — you will reach for it daily to inspect logs, find code, and build pipelines. The flags you choose completely change what it does.

Essential flags

FlagMeaningTypical use
-EExtended regex — enables +, ?, |, ().Almost always — use grep -E instead of bare grep.
-iCase-insensitive match.Searching logs where case varies.
-nPrefix each matching line with its line number.Jumping to the right line in an editor.
-oPrint only the matched text, not the whole line.Extracting values like error codes or IP addresses.
-qQuiet — produce no output, only set exit status.Scripts that check "does this pattern exist?"
-rRecursive search through a directory tree.Finding a function name across all source files.
-vInvert — print lines that do not match.Filtering out noise lines from a log.
-cCount of matching lines (not the lines themselves).How many errors are in this log?
-hSuppress the filename prefix when searching multiple files.Pipeline-friendly output: find … -exec grep -h 'pat' {} +

Building grep pipelines

The real power of grep comes from combining flags and piping results into other tools:

# Exact line-start match
$ grep '^ERROR' server.log

# Extended regex: WARN or WARNING
$ grep -E 'WARN(ING)?' server.log

# Extract just the error codes (e.g. "ERROR 404")
$ grep -Eo 'ERROR [0-9]+' server.log

# Count how often each error code appears, most frequent first
# (sort, uniq, and cut are introduced in section 2.7)
$ grep -Eo 'ERROR [0-9]+' server.log | sort | uniq -c | sort -nr

# Search all Python files for TODO or FIXME, with line numbers
$ grep -rEn 'TODO|FIXME' src/

# Quiet check in a script — only exit status matters
$ grep -q 'ERROR' app.log && echo "errors found"

More grep patterns

These cover the patterns you will reach for most often once you are past the basics:

# ^ anchors to start of line; $ anchors to end of line
$ grep '^ERROR' app.log          # lines that START with ERROR
$ grep 'failed$' app.log         # lines that END with failed
$ grep '^$' file.txt              # empty lines (nothing between start and end)
$ grep -v '^$' file.txt           # non-empty lines (invert the match)

# Optional character with ? (requires -E)
$ grep -E 'colou?r' docs.txt     # matches "color" and "colour"
$ grep -E 'WARN(ING)?' app.log  # matches "WARN" and "WARNING"
$ grep -E 'https?://' links.txt  # matches "http://" and "https://"

# -l: print only the filenames that contain a match (not the matching lines)
$ grep -rl 'TODO' src/            # which files have TODO?

# Context lines around a match
$ grep -A 2 'ERROR' app.log       # 2 lines After each match
$ grep -B 1 'ERROR' app.log       # 1 line Before each match
$ grep -C 2 'ERROR' app.log       # 2 lines Context (before AND after)

# Multiple patterns: lines matching EITHER pattern
$ grep -e 'ERROR' -e 'WARN' app.log
$ grep -E 'ERROR|WARN' app.log   # equivalent using alternation

Understanding -o with pipelines

The -o flag is key for data extraction. Instead of returning the whole matching line, it returns only the part that matched your pattern — one match per line, even if there are multiple matches on the same source line. This makes it straightforward to count, sort, or further process specific values:

# Log file contains lines like:
# 2026-05-01 ERROR 404 Page not found
# 2026-05-01 ERROR 500 Database error
# 2026-05-02 ERROR 404 Page not found

# -o extracts just the matching portion from each line
$ grep -Eo 'ERROR [0-9]+' server.log
ERROR 404
ERROR 500
ERROR 404

# Now easy to count
$ grep -Eo 'ERROR [0-9]+' server.log | sort | uniq -c | sort -nr
      2 ERROR 404
      1 ERROR 500
grep exit status
  • 0 — at least one matching line was found.
  • 1 — no matching lines found.
  • 2 — an error occurred (e.g., file not found).
This is why grep -q 'pattern' file && echo "found" works: the exit status drives the && branching.
Always quote the pattern grep -E WARN(ING)? file — the shell will try to glob-expand (ING)? before passing it to grep. Always single-quote regex patterns: grep -E 'WARN(ING)?'.
Try this Create a sample log and practise the grep flags: 
$ printf 'ERROR 404 Not found\nERROR 500 Server error\nWARNING high load\nERROR 404 Not found\n' > server.log

# Anchors and counting
$ grep '^ERROR' server.log
$ grep -c 'ERROR' server.log

# Extraction with -o
$ grep -Eo 'ERROR [0-9]+' server.log

# Optional character
$ grep -E 'WARN(ING)?' server.log

# Context lines
$ grep -A1 'ERROR 500' server.log
