2.7 Text Processing: sort, uniq, and cut

grep (section 2.6) selects which lines to keep. Three more tools — sort, uniq, and cut — then shape those lines into useful output. Together they form the backbone of Unix text-processing pipelines: cut extracts columns, sort orders rows, and uniq collapses duplicates or counts them.

ToolWhat it doesKey flags
sort Sorts lines alphabetically by default. Add -n for numeric order, -r to reverse. -n numeric · -r reverse · -u deduplicate · -t delimiter · -k key field
uniq Removes or counts adjacent duplicate lines. Always pipe sort first. -c count · -d only show duplicates · -i ignore case
cut Extracts specific columns from delimiter-separated or fixed-width text. -d delimiter · -f field(s) · -c character positions

cut — extracting fields

# CSV data: studentid,unit,grade
# 31234567,FIT2109,HD
# 31234568,FIT1051,D
# 31234569,FIT2109,C

# Single field
$ cut -d',' -f2 enrolments.csv       # second field (unit)

# Multiple fields
$ cut -d',' -f1,3 enrolments.csv     # studentid and grade
$ cut -d',' -f2- enrolments.csv      # field 2 to end of line

# Tab-separated files (TSV): tab is the default delimiter, so -d is not needed
$ cut -f2 data.tsv

# /etc/passwd: system user database, colon-delimited
# format: username:password:uid:gid:info:home:shell
$ cut -d':' -f1 /etc/passwd           # extract just the usernames

# Cut by character position: extract timestamp (first 19 chars)
$ cut -c1-19 app.log                   # e.g. "2026-05-01 10:32:44"

sort — ordering lines

# Default: lexicographic (alphabetical) — "10" comes before "2"
$ printf '10\n2\n1\n20\n' | sort        # output: 1, 10, 2, 20  ← wrong for numbers
$ printf '10\n2\n1\n20\n' | sort -n     # output: 1, 2, 10, 20  ← correct

# Reverse order
$ sort -nr numbers.txt                 # largest first

# Sort a CSV by the third field (grade), case-insensitive
$ sort -t',' -k3,3 -f enrolments.csv

# Deduplicate in one step (-u = sort then keep unique lines)
$ sort -u names.txt
Alphabetical vs numerical sort Never use bare sort on numbers — it sorts digit by digit, so 10 comes before 2. Always use sort -n when the values are numeric. This is the most common sort mistake.

uniq — collapsing or counting duplicates

# Remove adjacent duplicates (sort first, otherwise scattered dupes survive)
$ sort names.txt | uniq

# Count how many times each line appears
$ sort names.txt | uniq -c

# Show only lines that appear MORE than once
$ sort names.txt | uniq -d
Why sort before uniq? uniq only removes adjacent duplicate lines. If identical lines are scattered across the file, uniq alone will miss them. Sorting first brings all identical lines together so uniq sees and collapses them correctly.

Putting them together — full pipeline examples

# Count distinct units from a CSV, most enrolled first
$ cut -d',' -f2 enrolments.csv | sort | uniq -c | sort -nr
     42 FIT2109
     38 FIT1051
     21 FIT3155

# Count how often each error code appears in a log, highest first
$ grep -Eo 'ERROR [0-9]+' server.log | sort | uniq -c | sort -nr
      8 ERROR 404
      3 ERROR 500
      1 ERROR 503

# Extract timestamps from a log and find the top 5 busiest minutes
$ cut -c1-16 app.log | sort | uniq -c | sort -nr | head -5
Try this Create sample data and work through the pipeline step by step: 
$ printf '31234567,FIT2109,HD\n31234568,FIT1051,D\n31234569,FIT2109,C\n31234570,FIT1051,HD\n31234571,FIT2109,D\n' > enrolments.csv

# Step by step — watch what each tool adds
$ cut -d',' -f2 enrolments.csv
$ cut -d',' -f2 enrolments.csv | sort
$ cut -d',' -f2 enrolments.csv | sort | uniq -c
$ cut -d',' -f2 enrolments.csv | sort | uniq -c | sort -nr
Before running each line: predict what will change. This step-by-step approach is the right way to build and debug any pipeline.
