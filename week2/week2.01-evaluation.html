2.1 How the Shell Evaluates a Command

When you press Enter, the shell does not immediately hand your input to the operating system. It first transforms it through a series of steps. Understanding this pipeline of transformations is the foundation of writing correct shell commands — because what you type is often not what the shell actually runs.

The seven expansion stages

The Bash manual defines a specific order of expansions. Every command you type passes through these in sequence:

#ExpansionWhat happensExample
1 Tilde expansion ~ at the start of a word expands to $HOME; ~user expands to that user's home directory. cd ~/projects → cd /home/student/projects
2 Parameter & variable expansion $name or ${name} is replaced with the variable's value. echo $HOME → echo /home/student
3 Command substitution $(cmd) runs cmd and replaces itself with its output. echo "Today is $(date +%A)"
4 Arithmetic expansion $((expression)) evaluates the expression as integer arithmetic. echo $((2 + 3)) → 5
5 Word splitting After an unquoted expansion, the shell may divide the resulting text into separate arguments. By default it splits at spaces, tabs, and newlines. These separators are stored in $IFS, the Internal Field Separator. dir="my files"; ls $dir → ls receives two arguments: my and files.
6 Filename (glob) expansion A glob is a filename pattern that uses wildcard characters such as *, ?, or [...]. The shell replaces an unquoted glob with the matching filenames. ls *.txt → ls notes.txt summary.txt
7 Quote removal Quotes used to control the above steps are stripped before the command runs. The program never sees the quote characters themselves. ls "my file.txt" → program receives my file.txt (no quotes).
Common pitfall Word splitting (stage 5) happens after variable expansion (stage 2). This means a variable that contains spaces will be split into multiple arguments — unless you quote it. ls $dir and ls "$dir" can produce completely different results when dir contains a space.

Seeing word splitting clearly

An argument is one separate input value passed to a command. printf 'argument: <%s>\n' prints one line for every argument it receives, and the angle brackets make each argument's boundary visible:

$ label="Week 2 Materials"

# Unquoted: the expanded value is split into three arguments
$ printf 'argument: <%s>\n' $label
argument: <Week>
argument: <2>
argument: <Materials>

# Quoted: the expanded value remains one argument
$ printf 'argument: <%s>\n' "$label"
argument: <Week 2 Materials>

You rarely need to change $IFS. The important rule is that an unquoted expansion can be split at its separators, whereas double quotes preserve the expanded value as one argument.

Arithmetic expansion

Arithmetic expansion evaluates an integer expression and substitutes the result. It is useful for counters, offsets, and simple calculations directly in the shell — no external tool needed.

# Basic arithmetic
$ echo $((2 + 3))
5
$ echo $((10 / 3))   # integer division: rounds toward zero
3

# Using a variable
$ count=4
$ echo "Next: $((count + 1))"
Next: 5

# Increment a counter in a script and show the new value
$ errors=0
$ errors=$((errors + 1))
$ echo "$errors"
1

Command substitution

Command substitution runs a command and inserts its output into the command line. The result is subject to word splitting unless quoted.

# $(cmd) runs cmd and replaces itself with its output
$ echo "Today is $(date +%A)"
Today is Monday

# Unquoted substitution splits on newlines too
$ files=$(ls)           # each filename becomes a separate word if unquoted later
$ echo $files           # newlines collapsed to spaces — one long line
$ echo "$files"         # newlines preserved
Side note — research on real-world Bash bugs A study of real open-source Bash scripts found that the most common bug categories are quoting, word splitting, path management, command options, return values, and error handling — precisely the topics covered in this week's pre-reading. These are not obscure edge cases: they appear in widely-used, mature projects.

Try this Set msg="hello world" then compare: 
$ echo $msg
$ echo "$msg"
$ printf '%s\n' $msg
$ printf '%s\n' "$msg"
printf '%s\n' prints each argument on its own line — making word splitting visible in a way that echo cannot, because echo always joins arguments with spaces. With quoting, "hello world" is one argument and produces one line; without quoting, it splits into two arguments and two lines.
