3.8 VS Code Basics: Opening, Editing, and Saving

3.6 gave you the minimum set of Vim commands to survive. This page is the same idea for VS Code: before we get into tooling, navigation, refactoring, and debugging, you should be able to open a project, create and edit a file, and save your work without hunting through menus.

Opening a folder, not just a file

VS Code is project-oriented, so the normal starting point is opening a folder, not a single file — that is what makes the Explorer, search, and navigation features in the rest of this week possible. Use File > Open Folder… and pick the project's top-level directory. If you're already in a terminal inside that directory, code . does the same thing and opens VS Code pointed at the current folder.

Once a folder is open, VS Code remembers it (and how you had things arranged) the next time you launch it there — this is the "workspace state" idea from 3.4.

Creating and opening a file

There are two common ways to get a new file open for editing:

  • In the Explorer, hover the project's root folder and click the New File icon (or right-click and choose New File), then type a name.
  • Press Ctrl+N for a new untitled editor, type into it, then save it — VS Code will ask where and what to name it the first time.

To open a file that already exists, either click it in the Explorer, or use Quick Open (below) to jump to it by name instead of hunting through folders.

Editing is direct — there is no mode to switch

This is the biggest contrast with Vim. Click anywhere in the editor and start typing — there is no Normal/Insert distinction to think about. The trade-off is the one from 3.5: VS Code's non-modal editing is more approachable at first, but the keyboard-driven precision Vim gets from combining operators and motions has to be replaced with mouse selection, multi-cursor, and menu commands instead.

Saving

Press Ctrl+S to save the current file. An unsaved file shows a filled dot on its tab instead of the usual close (×) icon — that dot is the same "buffer differs from file" idea from 3.4, just rendered as a dot instead of an asterisk. If you'd rather not think about saving at all, File > Auto Save writes changes to disk automatically after a short delay.

The Command Palette: your escape hatch

Press Ctrl+Shift+P (Cmd+Shift+P on macOS, or F1 on either platform) to open the Command Palette and type what you want to do in plain words — "format," "toggle terminal," "organize imports." Every action in VS Code, whether or not it has a keyboard shortcut, is registered as a named command, and the Command Palette is the searchable list of all of them. You do not need to know the exact name either: it fuzzy-matches, so typing "org imp" still finds "Organize Imports."

This makes it more than a launcher — it is also how you discover shortcuts. Every matching command is listed with its keyboard shortcut on the right, if one is assigned. If nothing is shown next to a command, that command simply has no default shortcut, and the Command Palette is the only way to reach it quickly. This is exactly the fallback nano relies on by printing its shortcuts on screen in 3.2 — VS Code just makes you search for it instead of reading it off the bottom of the window.

Try this — go find two real shortcuts
  1. Open the Command Palette and type side bar. Find View: Toggle Sidebar Visibility and read off the shortcut shown beside it (it should be Ctrl+B / Cmd+B) — that's the fast way to hide the Explorer and get your code full-width.
  2. Open it again and type git. Scroll through the list of Git commands (Commit, Push, Pull, Stage Changes, and so on) and notice how few of them have a shortcut listed at all. That gap is exactly why the Command Palette matters: for the long tail of commands nobody bothered to bind to a key, it's the only fast way in.
Your own list may differ slightly depending on your VS Code version and installed extensions — that's the point of searching it yourself rather than memorising a fixed list.

Minimum survival set

Shortcuts below are for Windows/Linux. On macOS, use Cmd wherever you see Ctrl — except Toggle Terminal, which stays Ctrl+` on macOS too (macOS itself reserves Cmd+` for switching between windows of the current app, so VS Code deliberately doesn't remap it).

Try this Open a folder, create a new file called notes.txt, type a line of text, and save it. Then open a second file, and use Ctrl+P to jump straight back to notes.txt by typing its name instead of clicking for it in the Explorer.
