3.2 Terminal Editors: nano, Vim, and Emacs

Three terminal editors show up constantly on Unix-like systems, and each represents a different philosophy about what editing should feel like.

nano — small and friendly

GNU nano is a small, beginner-friendly text editor. It highlights features such as undo/redo, interactive search-and-replace, auto-indentation, line numbers, word completion, file locking, backup files, and internationalisation support. That combination explains why nano is often recommended to beginners: it is preinstalled on many Unix-like systems (including macOS), it shows common shortcut hints on screen, and it does not require you to learn a deeply modal interaction model before you can edit a file successfully.

In a terminal or remote session, you can type nano shell.sh and begin editing almost immediately, while still encountering important editor ideas such as cursor movement, search, save, and exit.

Vim — modal editing

Vim is a modal editor: text entry and command execution are separated into different modes. In Normal mode, keys are interpreted as commands. In Insert mode, keys are inserted as text. This can feel unusual at first, but it teaches an important lesson — efficient editing is not just about typing faster, it is about navigating, selecting, repeating, and transforming text with intent.

Even if you never adopt Vim as your main editor, it is worth knowing enough of it to make small edits in a terminal or remote session. In this unit you are not expected to master Vim, but you should be able to open a file, switch modes, move around, make small edits, save, and quit — that is covered in 3.6 and 3.7.

Emacs — an extensible environment

Emacs represents yet another philosophy. The GNU Emacs manual describes Emacs as advanced, extensible, customizable, and self-documenting, noting that it can control subprocesses, indent programs automatically, show multiple files at once, and edit remote files as though they were local. Emacs illustrates a broader point: some editors are not merely file editors but extensible working environments.

Terminal editing culture on Unix-like systems includes several different traditions: lightweight and beginner-friendly tools such as nano, highly efficient modal editors such as Vim, and large extensible environments such as Emacs. Understanding this landscape helps you interpret why different developers have such different editing habits — nobody is "wrong," they are optimising for different things.

Editors and strong opinions You will meet developers with genuinely strong feelings about which editor is "correct." Treat that as a sign that editor choice is part of professional identity, not evidence that one tool is objectively best for every task.
