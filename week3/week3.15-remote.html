3.15 Remote Editing with VS Code

One of the most useful capabilities of a modern editor is that it can support development on systems that are not local — a container, a remote machine, or Windows Subsystem for Linux — as a full-featured development environment. The benefits include working on the same operating system you deploy to, isolating the development environment from your local machine, keeping contributors on a consistent environment, using tools or runtimes unavailable locally, and accessing an existing development environment from multiple machines or locations. Where code is edited and where code runs do not have to be the same place.

VS Code Remote Development provides exactly this. It allows you to open a remote folder on any remote machine, VM, or container with an SSH server, and take advantage of VS Code's full feature set while interacting with files anywhere on the remote filesystem. You keep the familiar VS Code interface locally while editing files that live elsewhere and using tooling that executes in the remote environment.

Not just convenience — realism

Many authentic development tasks happen in environments where the local operating system, package set, or architecture is not the actual target. Remote development lets you edit on the same OS you deploy to, use remote hardware, or avoid polluting your local machine with project-specific dependencies. It also means that code does not necessarily need to be copied onto your local machine to be edited productively — extensions and commands can run directly in the remote environment, so no source code needs to live on the local machine at all.

Where the boundary actually sits The interface is local, but the filesystem may be remote. The editor is local, but the language service or runtime may execute remotely. Your laptop provides the window; the remote machine provides the real context in which the project builds or runs. An editor is not just a local desktop application — it can be a bridge between local interaction and remote execution.

This separation between "where you interact" and "where things actually run" will come up again later in this unit when you work with containers, remote systems, and reproducible environments.
