Recap: editor concepts

The big idea from the pre-reading
An editor is the interface between your intentions and a program's source: what you're changing lives in memory first, and only becomes real when you save. Every editor — however it looks — is built around that same idea.
Why it matters in the job
Professionals spend far more time reading and modifying existing code than writing new code from a blank file. Fluency with your editor isn't a nice-to-have — it's what lets you spend your attention on the problem instead of on the tool.
Today's goal
Turn what you can already explain into something your hands do without thinking.

Two families of editors

Terminal-based
Runs inside a terminal, no mouse required.
Popular names: Vim, Nano, Emacs.
GUI-based
A full graphical application with panels, mouse, and extensions.
Popular names: VS Code, JetBrains IDEs.

Today we go deep on two of these: Vim, for when a GUI isn't available, and VS Code, the GUI editor you'll likely use day to day.

You won't always have VS Code

Terminal editors matter because...
  • 🖥️ Remote servers — SSH into headless Linux machines.
  • 🐳 Containers & cloud — minimal images often ship only vi/vim.
  • 🚨 Production support — a fast fix when a service is down.
  • ⚡ Reliable over slow networks — no heavy GUI to drag over SSH.
  • 💼 A real professional skill — common in SWE, DevOps, sysadmin, and cybersecurity.
Goal
You don't need to master Vim — you need to be able to confidently make small edits when it's the only editor available.

Choosing a terminal editor: why Vim

nano
Easiest to start — shortcuts shown on screen. Fine for a one-line edit, but limited beyond that.
Vim
Modal editing takes practice, but it's fast, scriptable, and installed almost everywhere.
Emacs
Extremely powerful and extensible, but a much bigger investment to learn.
Why Vim, specifically
It (or its ancestor vi) ships by default on almost every Unix-like system. Unlike nano's convenience or Emacs's depth, Vim's real advantage is that it's always there when you need it.

VS Code: Basics

Key idea
  • Open a folder (File > Open Folder, or code .) — not just a single file.
  • Tabs & editor groups — every open file is a tab; groups let you split the window into panes.
  • Direct editing — no mode to switch between typing and commands, unlike Vim.
  • Integrated terminal — a full shell built into the same window.
  • Command Palette (Ctrl+Shift+P on Windows/Linux, Cmd+Shift+P on Mac, or F1 on either) — every action is a named, searchable command.

Shortcuts in this deck: Windows/Linux first, Mac second — Ctrl ↔ Cmd, Alt ↔ Option.

VS Code: Tooling

Key idea
  • VS Code is an editor connected to language tooling — some ships built in, richer support comes from an extension.
  • Built in: JavaScript, TypeScript, JSON, HTML, CSS.
  • Needs an extension: Python, Java, C/C++, and most other languages.
  • Hints range from squiggly diagnostics to Quick Fixes (Code Actions) that fix things for you — like organizing imports automatically on save.
Formatting
"How should this look?" Layout, spacing, indentation — style only.
Linting
"Does this look suspicious?" Unused imports, unreachable code — logic hints.

VS Code: Multi-File editing

Split editor
Compare files side by side. Ctrl+\ (Cmd+\ on Mac), or drag a tab to an edge.
Multi-cursor
  • Alt+Click (Option+Click on Mac) — add a cursor where you click.
  • Ctrl+D (Cmd+D on Mac) — select the next matching word too.
  • Ctrl+Shift+L (Cmd+Shift+L on Mac) — select every match at once.
  • Ctrl+Alt+↓/↑ (Cmd+Option+↓/↑ on Mac) — add a cursor on the line below/above.
  • Shift+Alt+drag (Shift+Option+drag on Mac) — column (box) selection.
  • Esc — back to a single cursor.

VS Code: Refactoring the code

Search & Replace
Edits raw text — blind to comments and strings. A workspace-wide replace can catch a false match inside a comment or test fixture, so always preview first.
Rename Symbol (F2)
Understands the program's structure and only changes real references. Needs the language's extension installed — without it, Rename Symbol isn't available.

Rule of thumb: reach for Rename Symbol first when renaming a code identifier; use Search & Replace for everything else.
