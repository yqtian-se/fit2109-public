3.1 What Is an Editor, Really?

It is easy to think of an editor as simply "the place where I type code." In practice, it is much more than that. It is the environment where you:

  • read unfamiliar files
  • compare related pieces of code
  • search for definitions
  • make precise changes
  • run formatting tools
  • inspect diagnostics
  • interact with terminals, version control, and remote systems

In other words, the editor is not just a writing surface. It is one of the main places where software understanding and software change happen. Strong editor habits do not only make your own work faster — they make it more accurate, more systematic, and more capable of working across larger codebases. An editor is not merely a text area; it is the center of a broader interface for projects, searches, diagnostics, terminals, and extensions.

Two families of editor

On Linux and other Unix-like systems, you will encounter both terminal-based editors and GUI-based editors.

Terminal editors run directly inside a shell session. They are especially useful on remote systems with minimal installations, or any situation where a graphical desktop is unavailable or inconvenient.

GUI-based editors, by contrast, provide richer project views, side-by-side panes, mouse interaction, integrated terminals, extension systems, and language-aware tooling.

Neither category is "the right answer" in every circumstance — each represents a different trade-off. Terminal editors usually start quickly, work well over SSH, and encourage keyboard-centred interaction. GUI-based editors usually provide more visible structure and stronger integration with language tooling. This week you should understand both: 3.2 looks at terminal editors, and 3.3 looks at VS Code as our running example of a modern GUI editor.
