Week 1: Introduction to the Shell

Pre-reading · FIT2109 · Monash University

By the end of this week you should be able to

  1. Explain what a shell is and why it exists alongside a GUI.
  2. Navigate the filesystem using absolute and relative paths.
  3. Create, copy, move, and remove files from the command line.
  4. Read and change file permissions.
  5. Explain how $PATH controls which programs the shell can find and run.
  6. Connect commands together using pipes and redirection.

A scenario

It is 11 pm. Your machine learning experiment needs 14 hours to run and your laptop battery won't last. Your team uses a shared Linux server — 32 cores, always on, sitting in a data centre you will never physically touch. A local server in the lab would have the same problem: you cannot sit next to it for 14 hours overnight. So you open a terminal, connect remotely over SSH, and the server's computing power is available to you from anywhere with an internet connection.

There is no desktop, no file manager, no right-click menu — just a prompt. That is not an oversight. Servers deliberately omit graphical interfaces: a GUI consumes memory and CPU that are better spent on the actual workload, and there is often no monitor attached anyway. Every major cloud provider — AWS, GCP, Azure — gives you a Linux server with a shell and nothing more. You set up the project directory, copy your dataset into place, make the training script executable, and pipe its output into a log file so you can check progress from anywhere in the morning. When the run finishes, a one-line pipeline tells you whether it succeeded.

This is not a contrived exercise. Cloud servers, university HPC clusters, CI/CD build machines, and production web servers all work exactly this way — Linux, no GUI, shell only. The shell is not a relic from the past; it is the control surface that underlies modern software work. Learning it this week means every tool you encounter later — Git, Docker, deployment pipelines — will make immediate sense.

Concept check — before you start When you double-click a program to run it, what actually happens between the click and the program appearing on screen? As you read, build a mental model of where the shell fits in that chain.
