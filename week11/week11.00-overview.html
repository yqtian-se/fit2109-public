Week 11: Metaprogramming & Automation

Pre-reading · FIT2109 · Monash University

"A good project can explain how to build, test, and run itself — without anyone having to remember."

By the end of this week you should be able to

  1. Explain why repetitive project tasks should be automated, and what automation gives a team.
  2. Describe metaprogramming and recognise it in shell commands, Makefiles, and build files.
  3. Read and write simple Makefiles for building and running projects.
  4. Explain how build tools use dependencies to rebuild only what has changed.
  5. Automate common workflows for C, Python, and Java projects.
  6. Describe how continuous integration runs these workflows automatically.

A scenario

You join a small team that has a C project, a Python script, and a Java service. Each has a "how to build it" answer, but none of those answers is written anywhere you can run. The C build lives in someone's shell history. The Python setup is a paragraph in a chat message from last term. The Java service builds fine on one laptop and fails on another. You can read the code, but you cannot yet trust a build.

A teammate adds three small files: a Makefile, a scripts/bootstrap.sh, and a pom.xml. Suddenly a newcomer can type make, ./scripts/bootstrap.sh, or mvn test and get the same result as everyone else. A fourth file, .gitlab-ci.yml, makes the server run those same commands on every push, so a broken change can be caught before anyone merges it.

None of those files is "the program". Each one is a description of how to produce, check, or run the program — a program about programs. That is the sense of metaprogramming we use this week: you start small, with the shell rewriting your own commands before they run, and finish with a repository that knows how to build and verify itself.

Concept check — before you start Run echo project/{src,tests,docs} in a Bash terminal and look at the output. You typed a single word containing braces, yet the output shows three separate paths. What did the shell do between your keystrokes and echo? Keep the answer in mind — it is the smallest example of this whole week, and section 11.2 explains it.
