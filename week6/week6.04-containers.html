6.4 Containers

A container is an isolated process with its own view of the filesystem. Unlike a virtual machine, it does not run its own kernel — it shares the host's kernel and uses two Linux kernel features to create the illusion of isolation.

The kernel features underneath

  • Namespaces control what a process can see. Each container gets its own namespace for the process tree, network interfaces, filesystem mount points, and hostname. From inside the container, it appears to be the only process on an isolated machine.
  • cgroups (control groups) control what a process can use. They set limits on CPU, memory, disk I/O, and network bandwidth per container.

Docker, Podman, and other container runtimes package these kernel features into a convenient workflow — but the underlying isolation mechanism is built into Linux itself.

macOS and Windows Containers use Linux kernel features. On macOS and Windows, Docker Desktop runs a lightweight Linux VM behind the scenes to provide that kernel. Your containers run inside that VM — you just don't see it. This is why Docker Desktop is needed on non-Linux hosts.

What containers give you in practice

  • Reproducibility. The container image specifies every file, library, and configuration. The same image produces identical results on any Linux-based host.
  • Isolation. A container's filesystem is separate from the host. Installing packages inside the container does not affect the host. Exiting the container leaves nothing behind (unless you explicitly persist data).
  • Speed. Containers start in milliseconds. You can spin one up, run a job, and discard it in the time it takes a VM to boot.
  • Portability. An image built on your laptop can be pushed to a registry and pulled onto a server or a colleague's machine without modification.
Side note — containers are not new The underlying ideas are older than Docker. BSD jails (2000) and Solaris Zones (2004) offered similar process isolation. Linux containers (LXC) appeared in 2008. Docker, launched in 2013, made the workflow approachable by adding image layering, a registry, and the Dockerfile build format. The technology became widespread; the plumbing was already there.
