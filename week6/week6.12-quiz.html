FIT2109 Week 6Self-check · 6 questions
Self-checkAbout 5 minutes

Can you explain the causal story?

Answer each question before opening its explanation. These questions check reasoning, not command memorisation.

1. Different install times

On Monday, pip install messagekit selects version 1.4. On Friday, the same command selects version 2.0. What changed?

Show explanation

The package index changed: a newer release became available. The unpinned command asks for a currently acceptable release, so the command text alone does not determine one version.

2. What a requirement controls

The file contains messagekit==1.4. Which decision does this record, and name one environment layer it does not record.

Show explanation

It records the selected package version. It does not select the Python runtime, operating system, system commands, kernel, or package installation location.

3. Why use two virtual environments?

App A needs messagekit==1.4 and App B needs messagekit==2.0. Why can two venvs solve the conflict?

Show explanation

Each venv has its own Python package location. App A and App B no longer compete for one installed package version. The venvs still use the Python interpreters from which they were created.

4. Python package or system package?

import requests succeeds, but launching curl --version fails because the command is missing. Why does installing requests with pip not fix the failure?

Show explanation

Requests is a Python package. Curl is a separate system command. Pip manages the selected Python environment; the image's system package manager must supply curl.

5. Why does the old image run old source?

You edit app.py and then run an image that was built before the edit. Which version of the file does the container start with?

Show explanation

It starts with the file captured in the existing image. Editing the host file does not rewrite that image. Rebuild to create image contents from the changed source.

6. Container or VM?

Which one boots a guest kernel: a Linux container or a virtual machine?

Show explanation

A VM boots a guest kernel. A Linux container shares the Linux host kernel while isolating processes and user-space state.
