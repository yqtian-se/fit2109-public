Self-checkAbout 5 minutes

Can you distinguish the layers?

Try these questions before class. They check whether you can tell the layers apart. You do not need the workshop example or its commands.

1. Direct and transitive dependencies

Your project names reportlib. During resolution, two additional packages are selected because reportlib needs them. How should the three packages be classified?

Show explanation

reportlib is a direct dependency because the project names it. The additional packages are transitive dependencies because they are required through another dependency.

2. Declaration and installed state

Why is a dependency file normally committed while a generated .venv/ directory is normally rebuilt?

Show explanation

The dependency file is a reviewable project description. The venv is generated installed state tied to a particular Python interpreter, platform, and local checkout.

3. The boundary of activation

Activating a venv changes which python command the current shell finds first. What mechanism changes, and what does not change?

Show explanation

Activation changes command lookup by placing the venv launcher directory near the front of PATH. It does not install another operating system, create a new kernel, or permanently change every terminal.

4. Package-manager scope

A media-report application can import its Python image library, but a separate video-conversion executable is absent. Why is the successful import not evidence that the executable exists?

Show explanation

The Python package and the system executable belong to different package-management scopes and installation locations. Satisfying one dependency layer says nothing about the other.

5. Isolation boundaries

Which tool primarily separates Python packages, which packages a user-space filesystem and processes, and which boots a guest operating system?

Show explanation

A venv separates Python package state. A container isolates application processes and a user-space filesystem view while using an existing Linux kernel. A VM boots a complete guest operating system and guest kernel.

6. Recipe and artifact

Why can reusing one tested image be more repeatable than rebuilding the same Dockerfile several months later?

Show explanation

The image records one constructed result. A later rebuild may resolve updated base images, repositories, or transitive dependencies even when the recipe text is unchanged.

Ready for classYou are ready if you can distinguish descriptions from installed state, identify a dependency's layer, and explain which boundary a tool controls.
