Python packages and system packages

A Python process can depend on both imported packages and programs supplied by the operating system. These are different package layers.

One application, two kinds of dependency

import requests
import subprocess

print(requests.__version__)
subprocess.run(["curl", "--version"], check=True)

requests is imported by Python. curl is a separate system command launched by the Python process. Not every host has curl installed.

pip does not manage every program on the machineRunning pip install requests does not install the curl executable. A venv can isolate Python packages, but it does not isolate or supply the host's system packages.

Why system setup becomes difficult

System packages depend on the operating-system release and configured repositories. They are often installed into shared machine state. Upgrading a shared library or command can affect several applications, and switching between two system-level versions may be difficult.

Inside a Dockerfile

The image python:3.12-slim is based on Debian, so its system package manager is apt-get. A typical non-interactive installation step is:

RUN apt-get update \
    && apt-get install -y curl \
    && rm -rf /var/lib/apt/lists/*

Another base image may use another package manager. For example, Alpine Linux uses apk. Read the base image documentation before choosing the command.

Concept check

The Python import succeeds, but subprocess.run(["curl", "--version"]) reports that the file is not found. Which dependency layer is missing?
