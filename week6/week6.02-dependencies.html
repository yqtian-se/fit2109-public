Dependencies change over time

The command can stay the same while the result changes. An unpinned install asks the package index what is available now.

Monday

The latest release is messagekit 1.4. The developer runs pip install messagekit, receives 1.4, tests the application, and commits only the source code.

Friday

messagekit 2.0 has been released with a major API change. A teammate runs the same install command, receives 2.0, and the application no longer starts.

The causeDifferent install times can select different versions when the dependency declaration does not constrain the version.

Record the tested direct dependency

Python projects commonly use a file named requirements.txt. For this small project, the developer records the exact direct package version that was tested:

# requirements.txt
messagekit==1.4

Another developer installs the declaration with:

python3 -m pip install -r requirements.txt

The exact pin makes this package choice repeatable. Tests still matter: a version number records what to install, while tests show whether the application works with it.

What this file does not recordThis one requirement does not choose the Python version, operating system, kernel, system commands, or installation location. The next pages add those controls one layer at a time.

Concept check
