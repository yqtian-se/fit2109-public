Week 6: Reproducible Environments

Pre-reading · FIT2109 · Monash University

"It works on my machine." — the most expensive sentence in software engineering.

By the end of this week you should be able to

  1. Explain why the same software can behave differently on different machines.
  2. Contrast virtual machines and containers and state when each is appropriate.
  3. Use core Docker commands to run, inspect, and remove containers.
  4. Read a Dockerfile and explain what each instruction does.
  5. Install packages with apt-get, pip, and npm.
  6. Create an isolated Python environment with venv and pin dependencies in requirements.txt.
  7. Explain what a lockfile is and why it matters.

A scenario

You push a bug fix at 9 pm. CI turns red. The error is ModuleNotFoundError: No module named 'cryptography'. On your laptop it runs fine. The CI server is Ubuntu 22.04; you are on macOS 14. The cryptography package you installed globally six months ago never made it into requirements.txt. Your teammate cannot reproduce the bug either — they have a different version installed. Nobody knows which version the production server has.

This is not bad luck; it is a solvable engineering problem. Reproducible environments eliminate the variables: you declare exactly what your software needs, lock those versions, and run inside an isolated environment that is identical everywhere. The CI server, your teammate's laptop, and production all start from the same specification. "Works on my machine" stops being a meaningful phrase.

This week gives you the tools: virtual machines for OS-level isolation, Docker containers for process-level isolation, and package managers (apt-get, pip/venv, npm) for library-level isolation. Together they cover every layer of the environment problem.

Concept check — before you start Think of a time a program worked on one machine but not another. What was different? As you read, map that experience onto the isolation layers introduced here. If you have not hit this problem yet, consider: what happens when you run a Python script that uses the int | str type-hint syntax (Python 3.10+) on a machine that has Python 3.8?
