The Week 6 map

Source code is only one input to a running program. Python, installed packages, system tools, files, and operating-system behaviour can also change the result.

The running example

A small Python application imports a package named messagekit and calls the system command curl. It works for its developer. A second person installs the project later and receives a different package version. Their program fails before they can even investigate the original task.

The causal story

  1. An unpinned install can select the newest package available at that time.
  2. A requirements file records the package version that the developer tested.
  3. A virtual environment gives each Python project its own package location.
  4. A system package manager supplies tools outside the Python package layer.
  5. A Docker image records a larger runnable environment that another machine can reuse.
Your preparation goalYou do not need to memorise Docker commands. Before class, be able to explain why each step exists and what problem it controls.
