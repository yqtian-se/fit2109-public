6.3 Virtual Machines

A virtual machine (VM) is software that emulates a complete computer — including hardware, firmware, and an operating system — running on top of another operating system. From inside the VM, everything looks like a real physical machine.

How a VM works

A piece of software called a hypervisor sits between the physical hardware and one or more guest operating systems. The hypervisor intercepts hardware requests from guest OSes and either emulates them in software or maps them to the real hardware efficiently.

  • Type 1 (bare-metal) hypervisors run directly on hardware with no host OS: VMware ESXi, Microsoft Hyper-V (server), Xen. Used in data centres.
  • Type 2 (hosted) hypervisors run as an application inside a host OS: VirtualBox, VMware Workstation/Fusion, Parallels. Common on developer laptops.

Each guest VM has its own kernel, its own memory allocation, and its own disk image. Guests are completely isolated: a crash inside the VM does not crash the host.

When to use a VM

  • Testing on a different OS. Run Windows inside Linux, or Ubuntu inside macOS, to test OS-specific behaviour.
  • Strong isolation required. A VM has its own kernel — a compromised guest cannot directly affect the host. Used for running untrusted code, browser testing, and security research.
  • Legacy software. Software tied to a specific OS version (e.g., an old 32-bit Windows application) can be preserved in a VM snapshot indefinitely.
  • Simulating a server environment. Spin up an Ubuntu 22.04 VM locally to match what your cloud provider gives you.

The cost of VMs

ResourceTypical overhead
Boot timeSeconds to minutes — a full OS must initialise.
Disk spaceGigabytes per image — the full OS filesystem is stored.
MemorySeveral hundred MB to several GB reserved per running VM.
CPUSome overhead from emulation; modern hardware virtualisation (Intel VT-x / AMD-V) reduces this significantly.
VMs are heavy by design Because each VM carries a full OS, you cannot run hundreds of VMs on a single laptop the way you can with containers. VMs are the right tool when strong isolation or OS-level fidelity matters — not for lightweight, fast-spinning development environments.
Side note — cloud VMs Every time you spin up a VM on AWS (EC2), Google Cloud (Compute Engine), or Azure (Virtual Machines), you are allocating a VM on a Type 1 hypervisor in a data centre. The cloud provider manages the hypervisor; you get the guest OS. This is exactly the same mechanism as VirtualBox on your laptop, just at scale.
