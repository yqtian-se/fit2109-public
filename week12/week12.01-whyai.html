12.1 Why GenAI Became Capable Now

Generative AI for code did not arrive gradually. It crossed a capability threshold in a short window, driven by three changes that happened simultaneously. Understanding what those changes were helps you reason about what these tools can and cannot do — and why their limitations are structural, not temporary bugs waiting to be fixed.

First, separate the concept from the product name. GenAI is the underlying capability: a model generates likely text, code, images, or other artefacts from a prompt. A GenAI API is the programmable interface that lets your own software call that model for a narrow task. ChatGPT, Claude, and Gemini are familiar chat interfaces around that kind of model. Codex CLI, Claude Code, and Gemini CLI are agent interfaces that let a model work closer to your files, shell commands, Git history, and tests.

Three shifts that changed the landscape

ShiftWhat happenedWhy it mattered
Architecture The Transformer architecture (2017) replaced older sequence models. Transformers use attention mechanisms that relate every part of an input to every other part, allowing them to handle long, structured text effectively. Previous models struggled with long-range dependencies in code — a variable defined 200 lines up, a function called 50 lines later. Transformers handle this naturally.
Scale Models were trained on essentially all public code available on the internet — billions of lines across GitHub, Stack Overflow, documentation, and tutorials. The sheer volume of diverse examples means the model has encountered most patterns that appear in everyday software work. It is not reasoning from first principles; it is completing patterns it has seen many times.
APIs Capability was packaged as a service. You do not need a research lab, a GPU cluster, or a machine learning background to use a frontier model — you call an API. This made it practical to build coding tools on top of models. Codex CLI, Claude Code, Gemini CLI, Cline, Aider, and Copilot are all, at their core, interfaces to an underlying model API.

Why code specifically?

Of all the things these models do well, code is where the gains have been most dramatic. There are concrete reasons for this:

  • Vast public supply. GitHub alone contains hundreds of millions of repositories. There is more high-quality, labelled code publicly available than almost any other structured data type.
  • Highly structured and consistent. Code follows strict syntactic rules, uses consistent naming patterns, and has predictable structure. This makes it easier for a model to learn and reproduce.
  • Correctness is measurable. Tests either pass or fail. This is unusually clear feedback compared to, say, evaluating whether a summary is accurate. It also means models can be fine-tuned using test results as a reward signal.
  • Huge demand willing to pay for it. Developer time is expensive. There is strong commercial pressure to invest in improving coding models, which drives continued progress.

What this means for you

These three shifts do not mean AI has become generally intelligent or reliably correct. They mean it has become very good at pattern completion over structured text. Code is structured text. So the model often produces code that looks syntactically right, follows common idioms, and resembles code that works — without any internal understanding of whether it actually does what you need.

The product examples will change. The important workflow idea is stable: a model API lets a program call a model; a chat interface helps you ask and receive; an agent interface can read, act, observe, and continue. That extra ability is useful, but it also increases the risk if you do not verify the result.
