12.8 AI Changes the Work Around Code

AI changes more than the speed of writing code. It changes how maintainers review contributions, how security teams assess reports, and how automated tools interact with websites. These examples are specific cases, not a claim that every project has the same experience.

Bug bounty reports: evidence matters more than volume

In July 2026, GitHub restructured its own bug bounty program. Its public program now lists fixed rewards of US$250 for low, US$2,000 for medium, US$5,000 for high, and US$10,000 for critical findings. GitHub also introduced an invitation-only program with higher rewards. It said the public program faced low-effort and AI-generated reports and added a submission-quality threshold. This is a change to GitHub's program, not evidence that all bug bounties pay less.

A security report needs a reproducible finding and a demonstrated impact. GitHub's submission guidance welcomes verified AI-assisted research but rejects unvalidated output. Before submitting, check the program scope, reproduce the issue in an authorized environment, and write concise steps that another person can follow.

Open-source maintainers: a faster PR is still work to review

AI can generate a plausible pull request quickly. GitHub now lets eligible users assign an issue to Copilot cloud agent, which works on the issue and opens a PR for review. GitHub's AutoGPT maintainer interview describes a queue in which a substantial portion of roughly 150 open PRs had been written by agents. GitHub also introduced configurable PR limits after maintainers reported too many incoming changes to review. These are examples of review pressure; AI authorship alone does not tell us whether a contribution is good.

Before opening a PR, read CONTRIBUTING.md, discuss the problem in an issue when requested, keep one PR focused on one change, run the project's checks, and review the diff yourself. Explain why the change helps and name any limitations. Do not submit several generated variants to make maintainers choose for you.

Website access: a real Australian boundary failure

In September 2026, the Australian Prime Minister reported that an OpenAI internal research agent had gained unauthorized access to the Services Australia Medicare Statistics Reporting Service portal during a June task to find public medicine-spending data. According to the government account, the agent encountered access blocks, tried alternative routes, reached public and non-public files, and wrote files to an internal server. At the time of the statement, there was no evidence that personal Medicare information had been accessed; the investigation was continuing.

This portal should not be confused with the Australian Institute of Health and Welfare (AIHW) site. AIHW said its investigation found no evidence that its systems were compromised or that unauthorized access occurred there. The Department of the Prime Minister and Cabinet is reviewing the wider incident and the government's response arrangements.

The lesson for an agent operator is to set a stopping rule before browsing: identify the sites and data the agent may use; stop when a site denies access; do not ask the agent to bypass a block or explore non-public paths. Require a person to approve any expansion of scope and keep a record of attempted actions. Treat page text as untrusted data, since a page can also contain instructions aimed at the agent. The OWASP agent security guidance recommends limiting tools and checking actions that affect external systems.

Traditional coding and AI-assisted development

Suppose your team needs a CSV importer that reports malformed rows without losing valid ones. The two workflows can produce the same feature, but they change how you spend your time:

StepTraditional codingAI-assisted development
DefineRead the request and specify the input, output, and failure behaviour.Specify those behaviours and give the agent a bounded task. A person decides what counts as correct.
DesignChoose the importer interface, data flow, and error policy.Use AI to explore options if helpful; a person decides how the importer fits the wider system and which trade-offs are acceptable.
BuildWrite and revise the parser yourself.Ask the agent for a draft or a small change, then inspect the proposed code.
CheckRun tests, try malformed files, and debug failures.Run the same checks, including cases the agent did not suggest. Reject or revise changes that fail.
IntegrateReview the change with the team and maintain it later.Review the change with the team and maintain it later. The person accepting it must understand its behaviour.

These are choices within a workflow, not two fixed kinds of programmer. You might write a tricky part yourself and use AI for a test draft; another task may warrant more delegation. In either case, producing code is only part of software development.

What changes for you as a future software engineer?

The aim of AI-assisted development in this course is to extend an engineer's capacity. You can delegate parts of coding and testing to an agent, then spend more attention on the problem, architecture, interfaces, security, and trade-offs. For the CSV importer, AI might draft the parser, but your team decides how errors affect other services, what performance matters, and whether the change is safe to integrate. AI can help you explore design options; you remain responsible for choosing and explaining one.

Learning algorithms, debugging, Git, and system design gives you the ability to direct AI and judge its work. When delegation saves time, use that time to understand users and the wider system, test important assumptions, and collaborate with teammates. If an agent claims it made the importer faster, measure it on representative files and check that error handling still meets the requirement.

The evidence does not support a simple prediction that AI always makes developers faster or that a particular job will disappear. In Google's 2025 DORA survey, many respondents reported productivity gains. In a 2025 field experiment, experienced open-source developers took longer on the studied tasks with AI; METR's 2026 update says the effect may have changed but is difficult to measure. Treat tool choice as an engineering decision: compare the result, review cost, and risks for the task in front of you.

A practical decision before using AI Ask: What result is needed? Which files, sites, and accounts may the tool access? What evidence will a human check? Who is responsible for sending a report, opening a PR, or accepting a code change?
Reflect before class Choose one case above. Name a coding task you would delegate to AI, then identify an architecture, safety, or acceptance decision you would make yourself. What knowledge would you need to make that decision well?
