12.9 Choosing AI Development Tools

Choose an interface based on the work you need done and the access you are willing to give it. Product names change; the difference between a chat, an API, an editor assistant, and an agent remains useful. Section 12.5 explains how project instructions, skills, MCP connections, and the harness fit around these interfaces.

Where the other concepts fit

A product is the interface you use. Project instructions give it local conventions; a skill can provide a reusable procedure; an MCP connection can expose external tools or data; and the harness controls what actions are possible. These layers may be present together, but none removes the need for a person to set the goal and judge the result. For example, GitHub's issue-to-PR workflow uses an issue as the task, repository instructions as context, and the PR as the result to review. The built-in GitHub connection does not require you to add an MCP server.

In Section 12.10, you will practise with an API example and an agent-produced change. As you work, ask which interface has the access the task needs, which action requires human review, and what evidence would convince you to accept the output.
