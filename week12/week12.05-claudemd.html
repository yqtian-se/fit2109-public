12.5 Project Context Files — Grounding the Agent

Every time you start a session, the agent arrives knowing nothing about your project. It does not know your naming conventions, which files are off-limits, how to run the tests, or what constraints the project is working under. Without guidance, it invents plausible answers to all of those questions — and those invented answers are frequently wrong.

A project context file solves this problem. In Claude Code, the file is CLAUDE.md. In Codex, the common project instruction file is AGENTS.md. Other tools may use their own filename or settings panel. The teaching idea is the same: write down the project facts the agent must not invent. Think of it as a README written for the agent, not for humans.

What to put in it

CategoryWhat to writeWhy it matters
Project purposeOne or two sentences on what the project does and its main components.Prevents the agent from misinterpreting the codebase as something it resembles superficially.
Build and test commandsExact commands: make test, pytest tests/, npm run build.The agent will run these to verify its changes. Without them, it guesses — or skips verification.
Naming conventionssnake_case, camelCase, file naming patterns, module structure rules.Prevents the agent from generating code in a different style to the rest of the project.
No-touch filesFiles the agent must not modify: migration scripts, generated files, third-party vendored code.The agent cannot infer which files are sensitive — it needs to be told explicitly.
Known constraintsNo new pip dependencies. No print() in library code. Python 3.11 only.Prevents the agent from introducing changes that technically work but violate project rules.

An example

# MyProject

## Build & test
- `make test` runs all tests
- `make lint` runs ruff

## Conventions
- snake_case for all functions
- No print() in library code
- Tests live in tests/

## Do not touch
- legacy/migration.py

This file takes about five minutes to write for a small project. For a larger project, a good project context file is the difference between an agent that makes sensible targeted edits and one that produces a diff you spend an hour untangling.

Without project context, the agent invents your project An agent without a context file will infer naming conventions from what it sees, assume the test command is pytest or npm test based on the project type, and decide for itself which files are important. These inferences are plausible but frequently wrong. The first time the agent runs the wrong test command, or edits a file you needed untouched, write the project instruction file your tool expects.
Try this — write a context-file stub Pick any project you already have on your machine (an assignment, a personal script, anything). Write a minimal project context file for it: one line describing what it does, the command to run the tests, one naming convention, and one file the agent should not touch. Use CLAUDE.md for Claude Code, AGENTS.md for Codex, or the equivalent file/settings for your tool. If you do not have a project handy, invent a tiny Python utility and write the context file it would need.
