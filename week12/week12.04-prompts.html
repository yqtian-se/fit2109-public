12.4 Give the Agent a Clear Task

A clear task, relevant context, and explicit boundaries help an agent produce a reviewable result. The prompt is one part of the workflow; tool access, repository state, and verification also matter.

What the agent needs for this task

  1. Task. State the behaviour you want changed. "Fix the bug" is vague; "In parse.py, parse_date() crashes on empty strings" identifies a case to address.
  2. Context. Give the project facts the agent cannot infer reliably from the files it can see, such as a compatibility requirement or the test command.
  3. Checks and boundaries. Say how you will judge the result and name constraints that matter: "Add a test for empty input" and "Do not change the function signature."

Vague vs specific

Vague prompt

"Fix my code."

The agent does not know which behaviour you want changed. It may ask for clarification or guess at the scope, leaving you with a result that is hard to review.

Specific prompt

"find_matches() in data.py is O(n²) because it searches a list on every iteration. Rewrite it to use a set for the lookup. Do not change the function signature or modify any test files."

The agent has a specific goal and a compatibility constraint. You still need to measure the result and inspect the diff.

Choose constraints that matter

"Add error handling to my script" leaves the required behaviour unclear. Say which error to handle, how the program should respond, and what existing behaviour must remain. Add a constraint such as "do not change the public function signature" when it matters to callers. A long list of generic rules can distract from the actual task.

Treat the prompt as a short specification with a way to check the result. For a CSV importer, you might ask the agent to preserve valid rows, report malformed rows, and add a test for both. Then inspect the change rather than assuming the wording alone guaranteed the outcome.

Put stable project facts in an instruction file

Your task prompt says what to do this time. A project instruction file records facts the agent should use across tasks: how to run tests, naming conventions, supported versions, and files it should leave alone. For example, put “fix parse_date() for empty strings” in the task prompt, and “run make test; use Python 3.11; do not edit generated files” in AGENTS.md or CLAUDE.md, depending on the tool. Check that the agent read the file. These instructions guide its work; permissions and sandbox settings control what it can access or change.

When the same multi-step procedure is useful for several tasks, a skill can hold that workflow and load when needed. The next page shows how task prompts, project instructions, skills, tool connections, and the harness fit together.

Keep the scope reviewable An agent given "refactor this module" may change the public API, rename functions, add a dependency, and reorganise files in one pass. If you only need a faster lookup, name that goal and any compatibility requirement. Review the diff and reject changes that do not serve the goal.
