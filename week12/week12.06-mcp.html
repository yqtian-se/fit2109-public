12.6 Model Context Protocol — Connecting Agents to the World

An AI model, on its own, can only work with the text you give it. It cannot open a file, query a database, create a pull request, or send a message. To do those things, it needs tools — and those tools need a consistent way to be described, discovered, and called.

Model Context Protocol (MCP) is the open standard that provides that consistency. Introduced by Anthropic in 2024 and now community-governed with adoption across multiple agent frameworks, MCP defines how an agent discovers what tools are available and how it calls them safely.

What MCP servers expose

TypeWhat it isExample
Tools Functions the agent can call to take an action. The agent decides when and how to call them based on the task. Run a SQL query, create a GitHub issue, send a Slack message, write a file.
Resources Data the agent can read. Resources are exposed as addressable content rather than executable actions. A file on disk, a database row, a document from a knowledge base.
Prompts Pre-built instruction templates that the agent can invoke by name, with parameters. "Summarise this PR", "Review this function for security issues".

MCP servers in practice

Filesystem
Read and write local files within a specified directory. Lets the agent work directly with your project without needing shell access to every path.
GitHub
List issues, create pull requests, read repository contents, post comments. Lets the agent interact with a repository as a collaborator would.
PostgreSQL
Query a database in read-only mode. The agent can answer questions about data, generate reports, or check schema without needing direct access credentials in the prompt.
Slack / Browser
Send and read messages in Slack channels, or navigate and extract content from web pages. These expand the agent's reach into communication and research tasks.

Why MCP matters

Before protocols like MCP, each agent tool was a custom integration — different APIs, different authentication patterns, different ways of describing what the tool could do. MCP standardises this so that any MCP-compatible agent can use any MCP-compatible server without custom glue code.

This has a practical consequence: an agent's capability is not fixed by its model weights. Every new MCP server that gets published makes every compatible agent more capable — without any change to the underlying model.

Why agents get more powerful without model updates When a new MCP server is released — say, one that can query your company's internal documentation — every agent that supports MCP can immediately use it. The agent's intelligence stays the same; its reach expands. This is why tool ecosystem growth matters as much as model improvement.
Each MCP server you add expands the agent's blast radius Adding an MCP server grants the agent a new category of capability. A filesystem MCP server lets it read and write files. A GitHub MCP server lets it create pull requests and push commits. A malicious or buggy MCP server can misuse those capabilities. Treat adding an MCP server like installing a package: check the source, understand what it exposes, and restrict it with --allowedTools if you only need a subset of its functions.
