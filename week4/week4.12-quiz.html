Quiz — 10 questions

4.12 Check Your Understanding

These questions are mostly about concepts rather than syntax recall. Think through each one — and commit to an answer — before opening the answer key at the bottom.

Question 1
Why does Git need git config --global user.name and user.email before you can commit?
Question 2
What does git add actually do?
Question 3
You edit a file after running git add on it, then run git commit without running git add again. What gets committed?
Question 4
You committed a file, then later added a rule for it in .gitignore. What happens?
Question 5
Why is Git's commit history described as a directed acyclic graph (DAG)?
Question 6
What is the key difference between a branch and a tag?
Question 7
When is it safe to use git commit --amend?
Question 8
Under what condition does a merge "fast-forward" instead of creating a merge commit?
Question 9
You are in the middle of editing a file and need to switch branches right now, but you are not ready to commit. What is the appropriate tool?
Question 10
Your local feature-readme branch has been merged into main. Which command safely deletes it locally, refusing if it turns out not to be fully merged?
Answer key — open only after committing to your answers
  1. Every commit records an author as part of its metadata — the name and email go into the commit itself (4.2).
  2. It takes a snapshot of the file's current content and stages it — nothing is committed or uploaded yet (4.3, 4.6).
  3. The version that was staged — git add captured the file as it was at that moment; later edits stay unstaged until you add again (4.6).
  4. Git keeps tracking it — .gitignore only affects untracked files; use git rm --cached to stop tracking (4.7).
  5. Pointers go from newer to older commits, and no commit can be its own ancestor — directed, acyclic (4.4).
  6. A branch is a movable pointer; a tag points at one fixed commit (4.5, 4.9).
  7. Only the most recent commit, and only if it hasn't been shared — amending replaces the commit, which rewrites history others may depend on (4.8).
  8. When the current branch head is an ancestor of the branch being merged — nothing has diverged, so the pointer just moves forward (4.9).
  9. git stash — it shelves uncommitted work so you can switch branches and restore it later (4.11).
  10. git branch -d — lowercase -d refuses to delete an unmerged branch; uppercase -D deletes regardless (4.10).
