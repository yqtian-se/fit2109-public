Tool focus: tabular data

10.7 Tabular Data Processing

Once data is tabular, the usual goals are to select columns, filter rows, and compute summaries. The catch is that "tabular" does not always mean "easy to split". You already know the standard line tools from Week 2 (2.7): cut prints selected parts of each line, sort orders lines, and uniq removes or counts adjacent repeated lines — which is why sort comes first.

Simple delimited data

Take a CSV with no quoted commas:

name,city,score
Alice,Melbourne,82
Bob,Sydney,75
Carol,Melbourne,91
Dave,Perth,75
# the city column (with its header):
$ cut -d',' -f2 scores.csv

# skip the header, then count each city:
$ tail -n +2 scores.csv | cut -d',' -f2 | sort | uniq -c
   2 Melbourne
   1 Perth
   1 Sydney

-d',' sets the delimiter and -f2 selects the second field. tail -n +2 starts output at line 2, so the header is skipped. Then cut extracts, sort clusters equal values together, and uniq -c counts each cluster. This is a classic wrangling pattern because each tool does exactly one job.

Two more small tools complete the set. sort -t, -k3 -nr sorts numerically (-n), highest first (-r), on comma-separated field 3 (-t, and -k3):

$ tail -n +2 scores.csv | sort -t, -k3 -nr | head -n 2
Carol,Melbourne,91
Alice,Melbourne,82
Common trap — sorting numbers as text Without -n, sort compares character by character, so 10 comes before 9 (because 1 < 9). Output like 10 100 9 is a classic sign you forgot -n.

Where line tools break: real CSV

Real CSV is often more complicated. RFC 4180 allows quoted fields that contain commas and even line breaks, so commands that split blindly on commas can misread perfectly valid files. Here is sales.csv:

date,customer,category,amount
2026-10-01,"ACME, Inc.",hardware,1250.00
2026-10-02,Globex,software,799.00
2026-10-03,Initech,software,500.00
2026-10-03,"ACME, Inc.",software,300.00
2026-10-04,Globex,hardware,450.00
$ cut -d',' -f2 sales.csv
customer
"ACME
Globex
Initech
"ACME
Globex

The customer "ACME, Inc." has been sliced in half — the output shows "ACME with a stray quote. Worse, there was no error: the command ran, printed plausible-looking output, and any total or count built on it is now wrong. Every cut, awk -F,, or sed pipeline that assumes one comma means one boundary has the same flaw.

Use a CSV-aware tool when quoting is possible

Miller (mlr) describes itself as being like sed, awk, cut, join, and sort for name-indexed data such as CSV. It reads CSV, TSV, JSON, and JSON Lines, understands RFC 4180-style quoting, and addresses columns by name rather than by position. The same cut that mangled "ACME, Inc." now just works:

$ mlr --icsv --opprint cut -f customer,amount sales.csv
customer   amount
ACME, Inc. 1250.00
Globex     799.00
Initech    500.00
ACME, Inc. 300.00
Globex     450.00

The flags say how to read and write: --icsv means CSV in, --opprint means a readable aligned table out (--ojson and --ocsv work the same way, and --c2p is shorthand for --icsv --opprint). Verbs such as cut are then chained with the word then.

Installing Miller

Miller is a single self-contained program, but it is not installed by default. Use the line for your system, then check it worked with mlr --version:

PlatformInstall command
macOS (Homebrew)brew install miller
Ubuntu / Debiansudo apt update
sudo apt install miller
 
$ mlr --version
mlr 6.22.0

The examples here are written for Miller 6, and the package that apt installs can be older on older Ubuntu/Debian releases, so check the version you got. The package name is the lowercase word miller, but the command it installs is mlr.

Miller in practice: filter, group, sort

Because Miller knows the column names and infers numbers, the common wrangling steps become short and readable. Revenue by category (the question from 10.1), then customers ranked by total:

$ mlr --icsv --opprint stats1 -a sum -f amount -g category sales.csv
category amount_sum
hardware 1700
software 1599

$ mlr --icsv --opprint stats1 -a sum,count -f amount -g customer \
    then sort -nr amount_sum sales.csv
customer   amount_sum amount_count
ACME, Inc. 1550       2
Globex     1249       2
Initech    500        1

$ mlr --icsv --opprint filter '$category == "software" && $amount > 400' sales.csv
date       customer category amount
2026-10-02 Globex   software 799.00
2026-10-03 Initech  software 500.00

stats1 computes statistics (-a) over a field (-f), optionally grouped (-g); filter keeps records for which an expression is true, with fields written $name. Writing CSV out re-quotes correctly, and Miller converts between formats too:

$ mlr --csv sort -nr amount then head -n 2 sales.csv
date,customer,category,amount
2026-10-01,"ACME, Inc.",hardware,1250.00
2026-10-02,Globex,software,799.00

$ mlr --icsv --ojson head -n 1 then cut -f customer sales.csv
[
{
  "customer": "ACME, Inc."
}
]
Miller vs SQLite Both are CSV-aware, so either is a sound answer to the quoting problem. Miller is a streaming tool that slots into a shell pipeline and converts between CSV and JSON. SQLite (10.9) suits questions that need several groupings or joins, and is usually already installed. In a Python project, the standard-library csv module is a third option.

The lesson is not that line tools are bad, but that you must know which kind of file you have before choosing. For easy cases they are excellent; for anything else, switch early.
