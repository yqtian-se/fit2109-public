Tool focus: jq

10.8 Structured Queries for JSON with jq

Text filters are excellent for line-oriented input; nested data is better handled by a structure-aware query. For JSON, the key command-line tool is jq. The jq manual describes a jq program as a filter: it takes JSON in and produces JSON out. Instead of treating JSON as a pile of lines, you navigate its objects and arrays directly. Here is orders.json:

{
  "orders": [
    {"id": 101, "status": "pending", "total": 49.95,
     "customer": {"name": "Alice", "city": "Melbourne"}},
    {"id": 102, "status": "shipped", "total": 99.50,
     "customer": {"name": "Bob", "city": "Sydney"}},
    {"id": 103, "status": "pending", "total": 15.00,
     "customer": {"name": "Carol", "city": "Melbourne"}},
    {"id": 104, "status": "pending", "total": 220.00,
     "customer": {"name": "Dave", "city": "Perth"}}
  ]
}

Build a query one filter at a time

The simplest filter, ., is the identity: it validates and pretty-prints. Filters join with |, just like shell pipes, but the data flowing through them is JSON rather than lines:

# validate + pretty-print:
$ jq '.' orders.json

# every element of the array:
$ jq '.orders[]' orders.json

# reshape each order:
$ jq '.orders[] | {id: .id, status: .status}' orders.json

# keep only pending orders:
$ jq '.orders[] | select(.status == "pending")' orders.json
FilterMeaning
.ordersThe value of the key orders
.orders[]Each element of the array, one at a time
.orders[0]The first element
.customer.cityReach into a nested object
select(condition)Pass the item through only if the condition is true
{id, total}Build a new object with just those keys (shorthand for {id: .id, total: .total})

Answering questions

That already answers the third question from 10.1 — which orders are pending? — and the rest follow the same pattern:

$ jq -c '.orders[] | select(.status=="pending") | {id, total}' orders.json
{"id":101,"total":49.95}
{"id":103,"total":15.00}
{"id":104,"total":220.00}

$ jq '[.orders[] | select(.status=="pending")] | length' orders.json
3

$ jq -c '.orders | group_by(.status) |
    map({status: .[0].status, n: length, sum: (map(.total) | add)})' orders.json
[{"status":"pending","n":3,"sum":284.95},{"status":"shipped","n":1,"sum":99.50}]

-c prints compact one-line JSON. Wrapping a stream in [ ... ] collects it back into an array so length can count it. group_by and add do the grouping and totalling inside jq itself.

Getting text back out: -r and @csv

By default jq prints JSON, so strings are wrapped in quotes. The -r (raw output) option prints strings without them, which is what you want when the output feeds another text command. For tabular output, @csv formats an array as a correctly quoted CSV row, which is safer than gluing fields together with commas by hand:

$ jq -r '.orders[] | select(.status=="pending") | "\(.id),\(.total)"' orders.json
101,49.95
103,15.00
104,220.00

$ jq -r '.orders[] | select(.status=="pending") |
    [.id, .customer.city, .total] | @csv' orders.json
101,"Melbourne",49.95
103,"Melbourne",15.00
104,"Perth",220.00

This is a nested-to-flat conversion: JSON in, a small CSV-style report out. Once the data is flat, line tools take over again — for example, pending orders per city:

$ jq -r '.orders[] | select(.status=="pending") | .customer.city' orders.json |
    sort | uniq -c | sort -nr
   2 Melbourne
   1 Perth

Missing keys do not raise errors

Remember from 10.3 that JSON does not guarantee every object has the same keys. jq is forgiving: asking for a key that is absent gives null, not an error. That is convenient, and it can also hide a problem:

$ echo '[{"id":1,"total":5},{"id":2}]' | jq -c '[.[].total]'
[5,null]

$ echo '[{"id":1,"status":"pending"},{"id":2}]' |
    jq -c '.[] | select(.status=="pending")'
{"id":1,"status":"pending"}

The second record has no status at all, so select quietly drops it — it is not counted as pending or as anything else. When completeness matters, count the objects that lack the key (select(has("status") | not)) or supply a default with // (for example .status // "unknown").

Validate first jq empty file.json prints nothing and exits 0 if the file is valid JSON, and exits non-zero with a parse error if not. It is a cheap first stage in any script that consumes JSON.
