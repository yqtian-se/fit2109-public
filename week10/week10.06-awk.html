Tool focus: awk

10.6 Fields and Aggregation with awk

sed thinks in characters; awk thinks in records and fields. The GNU Awk User's Guide explains that input is divided into records (by default, lines), and each record into fields (by default, runs of whitespace). Fields are named $1, $2, …, $NF is the last field, and $0 is the whole line. That field model makes awk the bridge between filtering and summarising.

Every awk program is built from pattern { action } pairs: for each record, if the pattern is true, run the action. Omit the pattern and the action runs for every record; omit the action and matching records are printed.

Extracting fields

2026-10-01 09:00:01 INFO  user=alice action=login
2026-10-01 09:00:05 ERROR user=bob code=503
...
$ awk '{print $3}' app.log          # the severity of every line
INFO
ERROR
WARN
...
$ awk '{print $3, $4}' app.log     # severity and user
$ awk '{print $NF}' app.log        # last field on each line

Filtering on a field, not on a substring

Here is the field-level test promised in 10.4. A pattern such as $3 == "ERROR" is true only when the third field equals ERROR exactly, so a line like INFO user=ERROR_handler is not matched:

$ awk '$3 == "ERROR"' app.log | wc -l
4
$ awk '$3 == "ERROR" && $5 == "code=503"' app.log | wc -l
3
$ awk '$3 == "ERROR" {print $5}' app.log
code=503
code=504
code=503
code=503

Summarising: counting and totalling with arrays

Because awk is a small programming language, it can keep running totals. An associative array is indexed by a string, which is exactly what grouping needs. A BEGIN block runs before any input and an END block runs after the last record:

$ awk '{n[$3]++} END {for (level in n) print level, n[level]}' app.log | sort
ERROR 4
INFO 2
WARN 1

For each line, n[$3]++ adds one to the counter named by the severity; the END block prints every counter. The same idea sums a numeric column. With -F, to set the field separator, and NR>1 to skip the header row, here is the total score by city for the small scores.csv from 10.7:

$ awk -F, 'NR>1 {s[$2] += $3} END {for (c in s) print c, s[c]}' scores.csv | sort
Melbourne 173
Perth 75
Sydney 75

NR is the current record number, so NR>1 means "everything after line 1".

Array order is unspecified for (key in array) visits keys in no guaranteed order, and the order can differ between awk implementations. If order matters in your report, pipe the output through sort, as above.
