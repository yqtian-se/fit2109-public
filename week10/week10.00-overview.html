Week 10: Data Wrangling

Pre-reading · FIT2109 · Monash University

"Data wrangling is the process of turning messy inputs into trustworthy outputs."

By the end of this week you should be able to

  1. Describe the four recurring stages of wrangling — inspect, filter/extract, transform, summarise — and apply them to a log, a CSV file, and a JSON document.
  2. Recognise plain text, CSV, and JSON by their structure, and choose a processing tool that matches each one.
  3. Tell a syntax problem from a data-quality problem, and diagnose encoding, line-ending, date, and missing-value issues.
  4. Filter and rewrite text with grep and sed, and select, test, and total fields with awk.
  5. Explain why naive comma-splitting fails on real CSV, and switch to a CSV-aware tool or SQLite.
  6. Query nested JSON with jq, and summarise results with sort | uniq -c, awk, or SQL.
  7. Build a pipeline incrementally, validate each stage, and save a reliable, re-runnable script.

A scenario

It is Monday morning and a teammate sends you three files from the same system: app.log, sales.csv, and orders.json. They want three answers by lunchtime — how many errors there were, which product category made the most money, and which orders are still pending. You already know how to open a terminal, chain commands with pipes, and search text with grep.

So you start with the log, and it goes well. Then you try the same cut-and-sort approach on the CSV, and the totals come out slightly wrong — with no error message at all. It turns out one customer is called "ACME, Inc.", and the comma in that name was treated as a column boundary. The JSON file defeats the line tools entirely, because it is a tree rather than a list of lines. And the accented names in a fourth file arrive as �.

None of this is bad luck. Each file has a different shape, and each shape has a tool built for it. Data wrangling is the habit of recognising the shape first, picking the matching tool, and checking every step of the pipeline so that a wrong answer never looks like a right one. This week turns the shell skills from Weeks 1–2 into an analysis toolkit.

Concept check — before you start Run echo 'a,"b,c",d' | cut -d',' -f2 in your terminal and look at the output. Is it what you would want from the second column of that CSV row? Keep the answer in mind — by section 10.7 you will know exactly what happened and what to use instead.
