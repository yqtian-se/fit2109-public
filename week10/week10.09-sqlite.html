Tool focus: SQLite

10.9 SQL on the Command Line with SQLite

Some questions are not about extracting a field but about relationships: group these rows, total that column, rank the results. You could build that out of awk arrays, but SQL is a language designed for exactly this, and SQLite brings it to the command line with no server to install or manage. The SQLite command-line shell can read a CSV file into a table, and it follows CSV quoting rules while doing so — which makes it a practical bridge between a raw CSV file and a real query.

Here is sales.csv again, including the quoted "ACME, Inc." that defeated cut in 10.7:

date,customer,category,amount
2026-10-01,"ACME, Inc.",hardware,1250.00
2026-10-02,Globex,software,799.00
2026-10-03,Initech,software,500.00
2026-10-03,"ACME, Inc.",software,300.00
2026-10-04,Globex,hardware,450.00

Import the CSV, then query it

Start the shell with a database file name (it is created if it does not exist). The dot-commands such as .mode and .import configure the shell itself; everything else is ordinary SQL, ending with a semicolon.

$ sqlite3 sales.db
sqlite> .mode csv
sqlite> .import sales.csv sales
sqlite> .headers on
sqlite> .mode column
sqlite> SELECT category, ROUND(SUM(amount), 2) AS total_revenue
   ...> FROM sales
   ...> GROUP BY category
   ...> ORDER BY total_revenue DESC;
category  total_revenue
--------  -------------
hardware  1700.0
software  1599.0

That is the second question from 10.1 — which category earns the most revenue? — answered with a relational question rather than by counting commas. .mode csv before .import tells SQLite to parse the file as CSV; because the table does not exist yet, SQLite creates it and uses the header row as the column names. A grouping query on the quoted customer behaves correctly too: "ACME, Inc." is one customer with two orders.

One-shot queries for scripts

In a script you rarely want an interactive session. sqlite3 accepts a database, optional setup commands, and a query on the command line; :memory: uses a throwaway in-memory database, and -csv or -column select the output format:

$ sqlite3 -header -csv :memory: -cmd '.import sales.csv sales' \
    "SELECT customer, SUM(amount) AS total FROM sales
     GROUP BY customer ORDER BY total DESC;"
customer,total
"ACME, Inc.",1550.0
Globex,1249.0
Initech,500.0

Note that the output is correctly quoted CSV as well — the round trip CSV → SQL → CSV does not corrupt the awkward field.

Common trap — imported columns are text When .import creates the table for you, every column is TEXT. You can see it with .schema: "amount" TEXT. Sums happen to work because SQLite converts numeric-looking text, but comparisons and sorting use text rules: ordering the values 9, 10, 100 gives 10, 100, 9. When a number must behave like a number, convert it explicitly: 
SELECT score FROM scores ORDER BY CAST(score AS INTEGER) DESC;
Alternatively, create the table first with the types you want, then import with .import --skip 1 file.csv table (the --skip 1 stops the header row being loaded as data).

Choosing SQL or line tools

Question shapeBetter fit
Pull one field out of every lineawk, cut, grep -o
Count how often each value occurssort | uniq -c (or GROUP BY)
Several groupings, totals, ranking, or joining two filesSQL
The data is already a table with quoting you cannot rule outSQL or Miller, not line tools

Structured queries become more valuable as structure increases. For nested JSON use jq; for tabular analysis with grouping and aggregation, SQLite is an excellent lightweight option. Good wranglers do not force every problem into regex.
