Tool focus: sed

10.5 Transforming Text with sed

grep selects whole lines. To change lines — strip a prefix, pull one value out of the middle, normalise spacing — you want sed. GNU sed describes itself as a stream editor: it reads input line by line, applies an edit, and writes the result to standard output, which is exactly the shape a pipeline stage needs.

Substitution: s/pattern/replacement/

Almost all everyday sed is one command, s. The text between the first pair of slashes is a regular expression; the text between the second pair replaces whatever it matched. -E selects extended regular expressions, as with grep -E.

Suppose you want to remove the leading timestamp from every line before grouping them:

$ sed -E 's/^[0-9-]+ [0-9:]+ //' app.log
INFO  user=alice action=login
ERROR user=bob code=503
WARN  user=alice retry=1
...

The pattern reads: at the start of the line, one or more date characters, a space, one or more time characters, and a space. The replacement is empty, so those characters simply vanish. Without the g flag, s replaces only the first match on each line; add g (s/a/b/g) to replace every match.

Try this Make a one-line test file so you do not touch real data:
echo "2026-10-01 09:00:01 INFO user=alice action=login" > /tmp/one.log
then run the sed command above on /tmp/one.log and confirm the timestamp disappears.

Capture groups: keep part of what you matched

Parentheses capture a part of the match, and \1, \2, … refer back to those captures in the replacement. That lets you extract a value instead of deleting around it:

$ echo "2026-10-01 09:00:05 ERROR user=bob code=503" |
    sed -E 's/.*user=([a-z]+) code=([0-9]+)/\1 \2/'
bob 503

Here the leading .* swallows everything up to user=, the first group captures the name, the second captures the code, and the replacement prints them separated by a space.

Two traps that bite everyone once

1. Lines that do not match pass through unchanged. sed prints every line, whether or not the substitution applied. If you extract the status code from the whole log, the INFO and WARN lines come out untouched, mixed in with your codes:

$ sed -E 's/.*code=([0-9]+).*/\1/' app.log | head -3
2026-10-01 09:00:01 INFO  user=alice action=login
503
2026-10-01 09:00:09 WARN  user=alice retry=1

The fix is -n (print nothing by default) together with the p flag (print only when a substitution happened):

$ sed -nE 's/.*code=([0-9]+).*/\1/p' app.log | sort | uniq -c
   3 503
   1 504

2. Matching is greedy. .* matches as much as it can, not as little. Try to strip HTML-like tags from <b>x</b> <b>y</b>:

$ echo '<b>x</b> <b>y</b>' | sed -E 's/<.*>//'

$ echo '<b>x</b> <b>y</b>' | sed -E 's/<[^>]*>//g'
x y

The first command printed an empty line: <.*> started at the first < and ran all the way to the last >, eating everything. The second uses [^>]* — "any run of characters that are not >" — so each match stops at the nearest closing bracket. Whenever you reach for .*, ask what it might swallow.

In-place editing is not portable GNU sed -i edits a file in place, but the macOS version needs a different form (-i ''). More importantly, in-place editing destroys your only copy of the data. In a wrangling workflow, write to a new file (sed ... raw.log > clean.log) and keep the original untouched.
