7.5 Building Your .bashrc: PATH, Aliases, Functions, and the Prompt

You now know which file your interactive shell reads — ~/.bashrc — and what a dotfile is. This section is about what to put in it. A minimal but genuinely useful one is only three lines long:

# ~/.bashrc
export PATH="$HOME/bin:$PATH"
alias ll='ls -lah'
PS1='\u@\h:\w\$ '

Those three lines happen to cover the three things people most often want from a shell: find my own commands, type less, and show me something useful at the prompt. The rest of this section takes them one at a time, in that order.

Line 1: making a PATH change permanent

This is the export from section 7.4, now made permanent. Typed at the prompt it lasted only for that shell; sitting in ~/.bashrc, it runs afresh for every interactive shell you open, so ~/bin is always on your search path and your own scripts are always runnable by name.

That is the general pattern for everything else on this page: anything you can type at the prompt, you can put in ~/.bashrc to have it apply automatically from then on.

Line 2: aliases, for typing less

Customisation earns its keep when it removes friction from things you do many times a day. The simplest tool for that is the alias — a short name that the shell expands into a longer command before running it. Aliases are created with the alias command and removed with unalias:

alias ll='ls -lah'       # long listing, human sizes, including dotfiles
alias gs='git status'    # the command you run most in any repository

Typing ll now runs ls -lah. Note how well the first one pairs with section 7.1: -a is what makes your dotfiles visible, so ll shows them by default.

Running alias with no arguments lists everything currently defined, which is a quick way to see what a shared machine or an inherited configuration has set up on your behalf.

When an alias is not enough: shell functions

Aliases have one firm limit: they are plain text substitution, so they cannot take arguments. Suppose you want mkcd, which should create a directory and move into it. As an alias there is nowhere for the directory name to go — the name you type would simply be appended to the end of the expansion, which is not what you mean. The Bash manual is explicit that shell functions are the right tool whenever arguments are involved:

mkcd() {
  mkdir -p "$1" && cd "$1"
}

Now mkcd project/notes creates the directory and changes into it. The "$1" is the first argument, exactly as in the scripts from Week 2 — and that is really all a function is: script code that lives in your shell instead of in a file, so it can be defined in ~/.bashrc and is available in every terminal.

A useful way to hold the distinction:

UseWhenExample
AliasA fixed shorthand for a longer command, with no arguments to placealias gs='git status'
FunctionYou need arguments, a condition, or more than one commandmkcd() { … }
ScriptThe tool is big enough to deserve its own file, or other programs need to run it~/bin/hello-fit2109

Functions sit deliberately between the other two: more capable than an alias, less ceremony than a script. Note also where functions sit in the command-lookup order from section 7.4: after alias expansion, but ahead of both builtins and the $PATH search. So defining a function named ls would shadow the real ls everywhere. That is occasionally useful and occasionally a trap.

Line 3: the prompt

The third line sets PS1, which stands for Prompt String 1 and controls what you see before every command you type. It is the piece of your environment you look at most, so it is worth more than a moment's thought — treated well it is not decoration but an information display.

Read PS1='\u@\h:\w\$ ' as a template: \u is replaced by your username, \h by the hostname, \w by the working directory, and \$ by $ (or # if you are root). The @, the : and the trailing space are literal characters that appear as typed. So for user alice on machine ubuntu in /home/alice/projects:

alice@ubuntu:~/projects$

You can make it carry more. This version adds the time and a count of background jobs:

PS1='[\A] \u@\h:\w jobs=\j\$ '

Here \A is the time and \j the number of jobs the shell is managing — background and suspended commands, the subject of section 7.7. Seeing jobs=1 sitting in your prompt is a useful reminder that something is still running. The escapes worth knowing:

EscapeShows
\uUsername
\hHostname, up to the first dot
\wWorking directory, with ~ for your home directory
\WJust the final part of the working directory
\$$ for a normal user, # for root
\jNumber of jobs the shell is managing
\ACurrent time, 24-hour HH:MM
\nA newline, so a long prompt can wrap onto its own line

Two pieces of advice. First, the prompt is redrawn before every single command, so anything slow you put in it makes the whole shell feel slow — these escapes are cheap, calling out to other programs is not. Second, resist the urge to show everything; a prompt crowded with information is one you stop reading.

Fun fact Hand-writing PS1 strings is still common, but a growing number of developers now use a prompt tool such as Starship instead — one config file that renders a richer, git-aware prompt showing things like the current branch and whether you have uncommitted changes. It is still worth learning the raw PS1 escapes first, the same way it is worth understanding recursion before reaching for a library that hides it.
Applying your changes Edits to ~/.bashrc affect shells started afterwards. To use them in the terminal you already have open, run source ~/.bashrc — the source command from section 7.2.

Three lines is a starting point, not a finished configuration. The next section adds the other setting most worth having in ~/.bashrc: how much of your command history the shell keeps, and how you search it.
