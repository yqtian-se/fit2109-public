7.6 Command History and Reverse Search

Your command history is itself something the environment configures — how much of it is kept, where it is stored, and how you search it are all settings, not fixed behaviour.

The history command lists previous commands, and a small set of history expansions let you reuse them without retyping:

history          # list recent commands with numbers
!!                # re-run the previous command
!$                # re-use the last argument of the previous command
!42               # re-run history entry number 42
!grep             # re-run the most recent command starting with "grep"

Far more useful day to day is incremental reverse search: press Ctrl-R and start typing — the shell searches your history live and shows the best match as you type. Press Ctrl-R again to step to an older match, and press Enter to run it, or the Right arrow / Esc to edit it first. Ctrl-R is a Readline binding, so it also works in the other command-line programs that use Readline.

Try this Press Ctrl-R right now in your terminal and type the first few letters of a command you ran earlier this session. Press Ctrl-R again to cycle to an older match.

Settings that control your history

How much history is kept, and where, is controlled by environment variables and shell options set in your startup files. The defaults are usually modest, and raising them costs almost nothing:

SettingWhat it controls
HISTSIZEHow many commands are kept in memory for the current session.
HISTFILESIZEHow many lines are kept in the history file on disk.
HISTFILEWhere that file lives. Defaults to ~/.bash_history.
HISTCONTROL=ignoredupsDo not record a command identical to the one before it. ignoreboth also skips commands typed with a leading space.
shopt -s histappendAppend to the history file on exit instead of overwriting it — important once you have more than one terminal open.

A reasonable set of history settings for ~/.bashrc:

# ~/.bashrc
HISTSIZE=10000            # commands remembered in this session
HISTFILESIZE=20000        # lines kept in ~/.bash_history
HISTCONTROL=ignoreboth    # skip duplicates and space-prefixed commands
shopt -s histappend       # append on exit rather than overwrite
Common trap Without histappend, each shell overwrites the history file when it exits — so the last terminal you close wins, and everything typed in the others is lost. If you routinely keep several terminals open, set it.

By default, Bash only writes history when a shell exits, so a command typed in one terminal is not searchable in another until you close the first one. If you want history shared between open terminals sooner, PROMPT_COMMAND — a variable holding a command that Bash runs automatically just before it redraws the prompt — can flush and reload it after every command:

# ~/.bashrc — write and re-read history after each command
PROMPT_COMMAND="history -a; history -c; history -r"

Here history -a appends new commands to the file, history -c clears the in-memory list, and history -r reads the file back in. The cost is that your Up-arrow history now includes commands from other terminals, which some people find convenient and others find confusing — try it and keep it only if you like it.
