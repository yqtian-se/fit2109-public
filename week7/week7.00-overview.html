Week 7: Command-Line Environment

Pre-reading · FIT2109 · Monash University

"The command line is not decoration — it is configuration, all the way down."

By the end of this week you should be able to

  1. Explain which startup files Bash reads for login, interactive non-login, and non-interactive shells.
  2. Trace how $PATH and command lookup decide which program a command name actually runs.
  3. Explain why programs read dotfiles at all, and configure your own with ~/.bashrc, ~/.inputrc, and ~/.vimrc.
  4. Search and manage command history with Ctrl-R and history-related environment variables.
  5. Write aliases, functions, and a custom prompt with PS1.
  6. Inspect what is running with ps, and control long-running commands with job control, signals, nohup/disown, and persistent tmux sessions.

A scenario

In Week 1 you learned that the shell finds a program by searching the directories listed in $PATH, and in Week 2 that export makes a variable visible to other programs. So you write a small script of your own, make it executable with chmod u+x, and drop it in a bin folder in your home directory. To run it by name from anywhere, you type export PATH="$HOME/bin:$PATH". It works.

Then you close the terminal. You open a new one, type the script's name, and get command not found — the change is gone, because it only ever applied to that one shell. Fine: you put the export line into a file called ~/.profile, because a web page said that is where it goes. Now it works when you SSH into the lab server, but it still does nothing in a new tab on your laptop. Nothing you typed was wrong, and yet the setting appears and disappears depending on how the terminal happened to be opened.

None of this is random. Bash reads a specific, predictable set of files depending on exactly how it was started — login or not, interactive or not — and putting a setting in the wrong one of those files is the single most common reason a customisation "does not work". Once you know the rule, "why is my PATH different in this terminal?" stops being a mystery and becomes a five-second diagnosis.

This week builds the layer above the shell commands you already know: the configuration, history, customisation, and process-management habits that turn a bare terminal into an environment you actually want to work in.

Concept check — before you start Open a fresh terminal on your own machine right now and run echo "$0" and echo "$-". Keep the output in mind — by the end of section 7.2 you will know exactly what it means.
