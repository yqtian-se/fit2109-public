7.8 Persistent Terminal Sessions with tmux and screen

Job control helps within a single shell, but it does not solve every problem. If your SSH connection drops, or you close your terminal window, ordinary shell jobs are interrupted. nohup and disown from the previous section keep a single command alive, but they do not give you back a working shell to check on it, run more commands, or arrange several programs side by side. This is where terminal multiplexers become valuable.

A terminal multiplexer is a program that runs inside your terminal and hosts several independent terminal programs within it. Its key feature is that the session it hosts belongs to the multiplexer, not to your terminal window. You can detach from a session — walk away, close the window, lose your connection — and the programs inside keep running on the machine. Later you reattach and find everything exactly as you left it.

Two programs do this: tmux and the older GNU Screen. If you are choosing one to learn, learn tmux — it is what most guides, dotfile collections, and colleagues assume today, it is actively developed, and its handling of split panes is far nicer than Screen's. The rest of this section is about tmux; Screen gets a short section at the end, because you will still run into it and should recognise it when you do.

Sessions, windows, and panes

tmux organises your work in three nested levels:

  • A pane is a single rectangular area running one shell or program.
  • A window is a full screen of panes — like a tab in a browser, it fills the display and you switch between windows one at a time.
  • A session is a named collection of windows. This is the unit you detach from and reattach to.

The terminal you are currently viewing a session through is called a client. A session with no client attached is simply detached — still running, with nobody watching. This model explains how a single SSH login can host an editor, a running server, and a log viewer at once, without opening three separate connections.

Managing sessions from the shell

These commands are typed at a normal shell prompt, either before you start using tmux or after you have detached from it:

CommandWhat it does
tmuxStart a new session with an automatic name (0, 1, …).
tmux new -s workStart a new session named work. Naming sessions is worth the extra typing.
tmux lsList all sessions running on this machine, showing name, window count, and whether a client is attached.
tmux attach -t workReattach to the session named work. tmux a -t work is the short form.
tmux new -A -s workAttach to work if it exists, otherwise create it. Useful in scripts and on remote machines, because it works either way.
tmux kill-session -t workEnd the session named work and everything running inside it.
tmux kill-serverEnd every tmux session on the machine. Use with care.

A typical first session looks like this:

tmux new -s work          # create and enter the session
# …work normally, then press Ctrl-b d to detach…
tmux ls
work: 2 windows (created Mon Aug 31 09:14:02 2026)
tmux attach -t work      # pick up exactly where you left off

Key bindings inside tmux

Once you are inside tmux, commands are issued with a two-step key sequence: press the prefix, release it, then press one more key. The default prefix is Ctrl-b. So "Ctrl-b c" means hold Ctrl and press b, let go, then press c.

KeysAction
Ctrl-b dDetach from the session, leaving everything running.
Ctrl-b %Split the current pane left/right.
Ctrl-b "Split the current pane top/bottom.
Ctrl-b ← ↑ → ↓Move between panes in that direction.
Ctrl-b zZoom the current pane to fill the window; press again to restore it.
Ctrl-b xClose the current pane (asks for confirmation).
Ctrl-b cCreate a new window.
Ctrl-b n / Ctrl-b pGo to the next / previous window.
Ctrl-b 0–9Jump straight to a window by number.
Ctrl-b ,Rename the current window.
Ctrl-b $Rename the current session.
Ctrl-b sShow an interactive list of sessions to switch between.
Ctrl-b ?List every key binding — the built-in reminder when you forget one.

GNU Screen: still around, and worth recognising

GNU Screen dates from the late 1980s and offers the same detach-and-reattach model with different key bindings: its default prefix is Ctrl-a rather than Ctrl-b. Almost nobody chooses Screen for a new setup now, but you still meet it mainly because it comes pre-installed on many systems where tmux does not, so it may be the only multiplexer available on a server you do not administer.

A minimal Screen workflow, enough to survive an unfamiliar server:

Command or keysWhat it doestmux equivalent
screen -S workStart a new session named work.tmux new -s work
Ctrl-a dDetach from the session.Ctrl-b d
screen -lsList available sessions.tmux ls
screen -r workResume the detached session named work.tmux attach -t work

If you find yourself using Screen regularly on a machine where you can install software, install tmux instead. If you cannot, these four commands will get your work to survive a dropped connection, which is the point.

Configuring them tmux and screen are separate programs, not shell features, so their commands and key bindings do not change with whichever shell you run inside them. Each has its own configuration dotfile — ~/.tmux.conf and ~/.screenrc, as mentioned in section 7.2 — written in the tool's own syntax rather than as shell commands.

Putting it all together

The three tools from this week's last two sections form a ladder, and the right one depends on how much you need to survive:

You want to…Use
Free up your prompt while a command keeps running in this shell&, Ctrl-Z, bg, fg
Keep one command alive after this shell closesnohup, disown
Keep a whole working session — several programs and panes — alive across a dropped connectiontmux (or screen, if it is all you have)

If you are running a long build, watching logs on a remote server, or editing and testing across several panes, tmux lets your work survive a lost connection and keeps related activities together in one place. Together with job control, these tools make the command line practical for real development and systems work.
