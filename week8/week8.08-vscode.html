8.7 VS Code Debugger

The VS Code debugger provides a graphical interface to the same concepts as GDB — breakpoints, step execution, variable inspection, and call stack navigation — but for Python, JavaScript, Go, and many other languages without needing to learn command-line syntax.

Key UI panels

  • Breakpoint (red dot in the gutter). Click to the left of any line number to pause execution there. Click again to remove it. Right-click for conditional breakpoints — pause only when an expression is true.
  • Variables panel. Shows every local and global variable in scope at the current pause point, with their live values. Expand objects and lists to inspect nested state.
  • Watch panel. Evaluate any expression you type (e.g. len(results), x * 2) at every step. Useful for tracking derived values.
  • Call Stack panel. Shows the full chain of function calls that led to the current pause. Click any frame to jump to it and inspect its local variables.
  • Debug Console. A REPL that runs expressions in the context of the paused program — evaluate, modify variables, or call functions interactively.

launch.json — configuring a debug session

VS Code stores debug configurations in .vscode/launch.json. For most Python scripts, the minimal config is:

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug current file",
      "type": "debugpy",
      "request": "launch",
      "program": "${file}",     // run whatever file is open
      "console": "integratedTerminal"
    }
  ]
}

Press F5 to launch this configuration. VS Code will ask you to create it if none exists.

The Watch panel in depth

The Variables panel shows every local variable in scope — useful, but noisy. The Watch panel shows only the expressions you choose, evaluated live at every pause point. This is where most of the real debugging insight comes from.

How to add a watch expression

  1. Open the Watch panel (left sidebar, under the debug icon, or via View → Run).
  2. Click the + button at the top of the Watch panel.
  3. Type any valid Python expression and press Enter.
  4. The expression is evaluated immediately and updated after every step.

What you can watch

A watch expression can be anything that is valid in the current scope — not just variable names:

ExpressionWhat it reveals
totalThe current value of a variable — same as Variables panel, but pinned.
len(results)How many items have been collected so far — without having to expand the list.
total / countA derived value — the running average — computed on every step without changing the source.
items[i]The element at the current loop index, updated as i advances.
expected == actualA boolean that turns False the moment the values diverge — instantly visible.
type(data)The runtime type of a variable — useful when the type is unexpectedly NoneType or str.

Watch vs Variables: which to use

  • Use Variables to get a broad picture of everything in scope when you first pause.
  • Use Watch to track specific quantities across many steps — especially derived values or comparisons that aren't stored in a variable.
  • Watch expressions persist across sessions, so your most useful expressions are ready the next time you debug the same file.
Watch expressions can call functions You can call any function that is in scope — for example, sorted(results) or ','.join(names). Be careful with functions that have side effects (writing files, mutating state) — evaluating them in the Watch panel will actually run them.
Why not just use print? print requires you to predict in advance which values matter and re-run the program after each addition. Watch expressions let you add, remove, and change what you track while the program is paused, without touching the source code.
Try this Write a loop that accumulates a total (e.g. summing a list). Set a breakpoint inside the loop. In the Watch panel, add three expressions: total, len(items), and total / (i + 1). Step through with F10 and observe all three update simultaneously. Does the running average match what you expect at each step?

Pausing when a variable changes — data breakpoints

Stepping line by line through a long loop to find the exact iteration where a variable goes wrong is tedious. A data breakpoint (also called a watchpoint) tells the debugger to pause automatically the moment a specific variable's value changes — no stepping required.

In VS Code

  1. Start a debug session and pause at any breakpoint.
  2. In the Variables panel, find the variable you want to watch.
  3. Right-click it and select "Break on Value Change".
  4. Press F5 to continue — execution will pause automatically the next time that variable is assigned a new value.
Support depends on the debugger extension Data breakpoints work reliably for C/C++ (via the C/C++ extension) and some other compiled languages. For Python (debugpy), support is available but may vary by VS Code version — if "Break on Value Change" is greyed out, use a conditional breakpoint instead (see below).

Conditional breakpoints — pause only when a condition is true

A conditional breakpoint is the universal alternative: the debugger evaluates an expression every time execution reaches that line and only pauses when it is True. This works in all languages VS Code supports.

  1. Right-click an existing breakpoint (the red dot) in the gutter.
  2. Select "Edit Breakpoint…".
  3. Choose "Expression" and type a condition, for example total < 0 or name == "alice".
  4. Press Enter. The dot gains a = symbol to indicate it is conditional.
  5. Press F5 — execution pauses only when the condition is met.
# Examples of useful conditional breakpoint expressions
total < 0          # pause the moment a running total goes negative
i == 999           # pause at the 1000th iteration of a loop
result is None     # pause when a function unexpectedly returns None
len(queue) > 100   # pause when a queue grows beyond a threshold

In GDB / LLDB

Both command-line debuggers have native watchpoint support via the watch command. GDB pauses execution whenever the watched variable is written:

(gdb) watch total       # pause on any write to 'total'
(gdb) rwatch total      # pause on any read of 'total'
(gdb) awatch total      # pause on read or write
(gdb) continue           # run until the watchpoint fires
Hardware watchpoint 2: total
Old value = 0
New value = -42
Try this Write a loop where a variable's value should only ever increase. Set a conditional breakpoint on the line that updates it, with the condition new_value < old_value. Run the program — the debugger will stop exactly at the first iteration where the invariant breaks, without you having to step through every loop cycle.
