9.5 cProfile: Which Function Is Slow?

cProfile is Python's built-in CPU profiler. It instruments every function call in your program and records how much time was spent in each one. After the program finishes, it prints a table ranked by your chosen column.

cProfile answers the first profiling question: which function is responsible for the most time? Once you have that answer, you use line_profiler to drill into the specific line.

Running cProfile

# From the command line -- no code changes needed
$ python3 -m cProfile -s cumtime app.py

# Show only the top 15 lines (pipe through head)
$ python3 -m cProfile -s cumtime app.py | head -20

Reading the output

   ncalls  tottime  percall  cumtime  percall filename:lineno(function)
        1    0.000    0.000    3.215    3.215  app.py:1(<module>)
        1    0.001    0.001    3.215    3.215  app.py:12(main)
        1    0.002    0.002    3.212    3.212  app.py:7(process)
        1    3.210    3.210    3.210    3.210  app.py:3(slow_op)
        1    0.004    0.004    0.004    0.004  app.py:9(fast_op)

Column meanings

ColumnMeaningWhen to use it
ncallsNumber of times this function was called.Large ncalls on a slow function means a hot inner loop — consider caching or restructuring.
tottimeTime spent inside this function only, excluding time in functions it called.The true cost of this function's own code.
cumtimeTotal time including all sub-calls. This is the column to sort by first.Reveals which function is responsible for the most time, even if its own code is fast.
percallAverage time per call (two columns: tottime/ncalls and cumtime/ncalls).Compares cost per invocation across functions called different numbers of times.
Sort by cumtime first, tottime second cumtime shows you the function that is responsible for the most time — even if it delegates that work to sub-calls. Once you find the high-cumtime function, look at its sub-calls or switch to tottime to find the function whose own code is burning CPU cycles.

Sort options

  • -s cumtime — sort by cumulative time (start here)
  • -s tottime — sort by time in the function body (find where CPU actually burns)
  • -s ncalls — sort by number of calls (find unexpectedly hot functions)
cProfile adds overhead Instrumenting every function call slows the program down — typically 10–50×. This means the absolute times are inflated, but the relative ranking of functions is reliable. Use cProfile to find the bottleneck, then benchmark the fix without cProfile.
Try this Run python3 -m cProfile -s cumtime on any Python script that takes more than a second. Find the function with the highest cumtime that is in your own code (not a standard library function). That is your first optimisation target.
