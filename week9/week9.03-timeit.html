9.3 timeit: Micro-benchmarks with Reduced Noise

The time command measures a whole program run. When you want to compare two Python expressions or small functions, you need something more precise — one that runs the code thousands of times, averages the results, and controls for garbage collection. That tool is timeit.

Why timeit instead of time.time()?

A naive manual timer like start = time.time(); ...; print(time.time() - start) has several problems:

  • A single run is dominated by noise — GC pauses, OS scheduling jitter, cache effects.
  • You have to choose the number of repetitions yourself, often guessing wrong.
  • Garbage collection may fire mid-measurement, inflating the result.

timeit solves all three: it disables GC during the timed section, automatically determines how many repetitions are needed for a stable result, and reports the best time across multiple trials.

Command-line usage

# Basic: time a single expression
$ python3 -m timeit "sum(range(1000))"
50000 loops, best of 5: 18.3 usec per loop

# With setup code (not included in the timed section)
$ python3 -m timeit \
    -s "data = list(range(10000))" \
    "sum(data)"
200000 loops, best of 5: 48.2 usec per loop

# Compare two approaches: string concat vs join
$ python3 -m timeit \
    -s "items = list(range(500))" \
    "result = ''; [result := result + str(i) for i in items]"

$ python3 -m timeit \
    -s "items = list(range(500))" \
    "''.join(str(i) for i in items)"

Key flags

FlagMeaningDefault
-n NRun the statement N times per trial.Auto-determined

-u UNITTime unit for output: nsec, usec, msec, sec.Auto

In-script usage

import timeit

# Time a snippet directly in Python code
t = timeit.timeit(
    stmt="'-'.join(str(i) for i in data)",
    setup="data = list(range(1000))",
    number=10000
)
print(f"Total for 10000 runs: {t:.4f}s  →  {t/10000*1e6:.2f} µs/call")
timeit reports the best result, not the average This is intentional. The best result reflects the code running without interference from the OS or GC. Averages are skewed upward by rare bad runs. When comparing two implementations, compare their best results.
timeit is for expressions, not programs Use timeit to compare two ways of doing the same small operation. Use time or hyperfine for whole-script benchmarks. Use a profiler when you need to know where inside the script the time goes.
Try this Use timeit to compare two Python expressions that accomplish the same thing — for example, [x**2 for x in range(1000)] vs list(map(lambda x: x**2, range(1000))). Which is faster? By how much?
